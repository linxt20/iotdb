# A–D 完整实现补全核查

目的：核对 A、B、C、D 的生产实现、原退出要求和实际执行证据，并固定 E 的实施前置条件。

摘要：一条查询拆成多个执行分支后，系统仍须保持结果、顺序和资源释放正确。本文把生产源码、局部断言、完整模块和真实查询分别绑定执行证据。不同源码的结果保留各自范围。运行工具另存版本，以便复核实际入口。

结论：最终冻结源码已完成完整模块、核心双节点、统计 RPC、严格三十二桶、五类一般资源、真实数据非法块、补充边界及格式与双语言构建验收。原八项反证适用性和新增算法正反测试均已核对。大输入验证只覆盖候选侧活性，冻结 A 压力超时保持原范围。十九份文档已完成三端首轮一致性核对，最终修订由外部发布回执核对。E 处于设计阶段。

## 验收对象

完成要求是相同源码下的生产接线、原合同断言、完整模块和真实查询都有有效回执。HEAD 相同的工作区仍可能含不同修改，因此每次执行必须绑定源码清单与实际加载文件。

例如，两个服务都显示相同提交时，服务包仍可能来自不同源码。只有源码清单、发行包和实际类加载来源同时匹配，才能归为同一验收对象。

数据来源：[运行字段来源](A-D_运行字段来源_20261102.json) 的 productionArtifactIdentity 是生产身份入口，finalAcceptance 是验收入口。最终清单覆盖 9,212 个文件。其 SHA256 以 7f4e99b8 开头，发行 ZIP 以 6879294f 开头，服务 JAR 以 1d5b31f6 开头。完整 SHA、持久目录及逐文件运行缓存核对回执由该 JSON 保存。

## B 构造、派发与清理

设备、时间分区和有序扫描共用构建器。登记表在资源创建后立即接管责任，完整树构造后冻结额度。父根接管子树时转移关闭责任。真实取消处理全部相关片段，并移除查询共享映射。

无序表模型收集器循环检查就绪子流，任一子流完成等待即可唤醒。每个当前等待只登记一个监听器，监听器只唤醒驱动，驱动线程处理失败和取消。表模型的受检内存估计覆盖同时存活的子流、收集器与引用对象。

例如，一个子流等待时，另一子流已有数据，收集器可以先读取后者。两个子流各保留十和二十字节、峰值分别为一百和七十字节时，整体峰值估计必须包含另一个子流的保留量。

数据来源：[B 实施记录](B_静态数据并行统一实施记录_20261031.md) 定位构建与生命周期文件。新增实现由 `/root/w5-docs/B_无序Collect活性补充设计_20261103.md` 和对应实现规划定义，精确测试由运行字段来源的 fairCollectAndCheckedTableMemory 保存。

## E 文档

E0 至 E5 处于设计与实现规划阶段。E 需要普通查询独立历史、规划期读取、实际驱动与扫描桶配对，以及动态决策回执。A–D 的原退出与 E 实现分别验收。
