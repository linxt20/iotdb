# B 静态数据并行统一实施记录

目的：记录 B 的扫描构建、资源冻结、所有权移交和多源执行实现，并对应可复核的测试证据。

摘要：B 把设备、时间分区和有序扫描统一到公共构建器。资源登记保存实际对象及记账键，冻结后沿用兼容额度。生命周期处理覆盖部分构造、取消和失败清理。多源运行另核对派发依赖、通道背压和结束通知。

结论：B 的公共构建与资源治理已经进入生产源码，物理别名及完整生命周期具有各自证据，最终包已完成核心、单源三十二桶与一般资源服务。无序收集和受检内存估计已接入表模型入口，并完成候选大输入活性验证。完整退出按原 B0 至 B6 逐项核对。生产身份、历史回执及验收范围统一由 [A–D 完整核查](A-D_完整实现补全核查_20261102.md) 维护。

## 扫描构建背景

扫描拆分必须保持每行读取一次，并在成功、取消及失败后释放资源。增加驱动数量只改变执行方式，业务结果和排序要求保持一致。

例如，十二个设备分到四条扫描流水线，每个设备必须恰好归属一个桶。根合并流水线负责收集结果，其自身不重复拥有设备。

数据来源：工程为 sc01 `/root/iotdb`，分支为 `feat/next-p0`。固定基线为 `8d5d9c6a2c838e42f21be9ebd3278151fb75c520`。文件处理依据为 [B 设计](B_静态数据并行统一设计_20261031_实施版_复审修订.md) 和 [B 实现规划](B_静态数据并行统一实现规划_20261031_实施版_复审修订.md)。

## B0 身份冻结

基线、工作区、依赖和配置分别冻结。运行入口保存绝对路径及 SHA，服务启动后核对实际加载类和 JAR。保留的安全测试资源独立登记。

数据来源：初始冻结证据为 `/root/property-b-artifacts/B0-20261031-01/`，补全身份见 A–D 核查的源码 manifest。

## B1 至 B3 计划与公共构建

纯规划器生成不可变工作单元和扫描桶。公共构建器负责子上下文、本地交换、流水线工厂、内存估计父关系和父端 ExchangeOperator。三类扫描入口只负责各自扫描根。

有序模式先合并每个桶的单设备有序扫描，再由根合并各桶。无法证明自然顺序、存在全局限制或共享溢写源时，按安全原因回退。

例如，两个桶各自按时间输出有序流，根必须使用合并排序，才能保持所有行的整体时间序列。

数据来源：计划由 `ScanParallelPlan` 和 `ScanParallelPlanner` 描述及生成。构造入口为 `LocalScanPipelineBuilder` 与 `DataNodeTableOperatorGenerator`。扫描规划单元为 `ScanParallelPlannerTest`。设备与时间分区单元为 `DeviceTableScanParallelPipelineTest` 及 `DeviceTimePartitionMorselTest`。

## 无序收集与表模型内存估计

无序表模型收集器轮询就绪子流，任一等待结束即可唤醒驱动。每个当前子 future 只登记一个监听器，监听器只负责唤醒，失败与取消在驱动线程处理。有序合并继续使用原排序语义。

表模型使用受检估计器累计同时存活的子流保留量，并计入收集器持有的引用、数组和唤醒对象。TREE 工厂沿用原选择，TABLE 构造入口统一接入新估计器。

例如，一个子流等待而另一个已有输出时，收集器继续读取后者。两个子流保留十与二十字节，峰值一百与七十字节，返回八与十二字节时，指定场景峰值预期为一百二十字节。

七类八十三个唯一方法通过。全子流等待与仅取最大子流两种变异各命中一个指定断言，错误数为零，恢复算法后两个断言通过。实际候选原预算大输入的范围见中央核查。

数据来源：实现为 `TableReadyCollectOperator`、`CheckedTablePipelineMemoryEstimator`、`DataNodeTableOperatorGenerator` 和 `LocalExecutionPlanContext`。补充合同为 `/root/w5-docs/B_无序Collect活性补充设计_20261103.md` 与 `/root/w5-docs/B_无序Collect活性补充实现规划_20261103.md`，精确源码及回执由运行字段来源的 fairCollectAndCheckedTableMemory 保存。

## B4 资源登记与额度冻结

登记表按物理对象身份去重，并保存真实内存记账键。父子流水线共用登记表。完整树构建后冻结一次，冻结后新登记必须失败。

名义份额用于诊断，执行额度保留兼容规则。共享队列额度采用原子取最小，已有缓冲与 future 保持其申请语义。普通本地 source 继续保留空 setter，并登记真实生产方队列键。各次额度请求先记录，完整树构建结束后按物理对象合并发布一次。父 shuffle 的构造门限与通道生效额度分别冻结。

例如，两侧分别申请八 MiB 和四 MiB 额度，共享队列最终取四 MiB。冻结过程不丢弃在途数据，也不重复预留。

数据来源：登记实现为 `LocalExecutionResourceRegistry`。原子额度实现为 `SharedTsBlockQueue`，完整树入口为 `LocalExecutionPlanContext.freezeResourceQuota()`。测试包括 `LegacyQuotaPublicationTest` 和 `SharedQueueQuotaAtomicityTest`。真实三十二通道的单元形态只有一个生产方记账键。诊断份额为 125,703 字节，实际发送块为 174,120 字节，生效额度为 4,022,509 字节。块大小介于诊断份额与生效额度之间，因此该测试可以检查兼容额度是否被错误收紧。

数据来源：实际通道与额度断言为 `LocalExecutionResourceRegistryTest` 和 `BQuotaCompatibilityContractTest`，通过记录见 A–D 核查的构建与回归。

## B5 所有权与失败清理

独立扫描根在创建后立即登记。父算子接管子根时同步更新关闭责任。factory 成功创建驱动后，关闭责任只交给该驱动。创建和未消费关闭共用同一同步边界。

部分失败先关闭已建驱动，再关闭未消费工厂及孤立根。每个关闭槽只结算一次，清理异常保留 suppressed。data 与 schema 共用同一驱动创建辅助方法。

取消请求提前发布，并在每次创建前后检查。最终调度移交与取消共用片段上下文的 monitor。规划上下文在成功移交或失败清理后解除引用。

例如，取消发生在 factory 返回与调度之间时，已创建驱动由创建循环关闭，禁止继续移交调度器。失败后交换与算子预留均须恢复。

数据来源：驱动工厂与片段管理为 `PipelineDriverFactory` 和 `FragmentInstanceManager`。片段上下文与本地规划为 `FragmentInstanceContext` 和 `LocalExecutionPlanner`。生命周期测试为 `PipelineDriverFactoryLifecycleTest` 与 `FragmentDriverCreationLifecycleTest`。登记及内存测试为 `LocalExecutionResourceRegistryTest` 和 `LocalExecutionPlannerOperatorsMemoryTest`。资源审计与注销回执由 `MPPDataExchangeManager` 和 `MPPDataExchangeServiceMBean` 暴露。

## 本地资源观察

本地观察窗口只在显式开启后采集生命周期。窗口按真实对象去重，保存实际驱动、未消费工厂、队列、端点和未完成 future。它还读取片段预留和交换池剩余量，并保留注销前后的回执。

窗口同时最多四个，默认持续一百二十秒，显式时长最多六百秒。每个窗口最多保存四千零九十六个片段。超限、过期或关联缺失时，读取标记证据不完整。关闭和过期均移除对象引用。全局注销回执另受四千零九十六条上限约束。

例如，强制注销前片段仍有二十万字节，注销后映射消失时，窗口仍保留失败回执。后续的零读数不能覆盖这条泄漏证据。非强制注销暂时保留非零账户时，窗口等待实际释放后的最终回执。

观察中的完整片段身份包含查询 ID。内存池继续按查询 ID 和短片段 ID 分层记账。例如，完整身份为 q.3.i0 时，账户查询键为 q，片段键为 3.i0。两种格式必须通过显式转换关联。

数据来源：窗口实现为 `ResourceAuditManager`，本地入口为 `MPPDataExchangeServiceMBean`。接口包含开启、枚举真实片段、读取和关闭。片段账户由 `MemoryPool.snapshotFragmentReservations()` 读取。管理器和工厂测试为 `ResourceAuditManagerTest` 与 `ResourceAuditFactoryProductionTest`。集成测试为 `BResourceObservationIntegrationTest`，最终通过状态以对应运行回执为准。

资源窗口还动态读取本节点的共享查询上下文映射。该值来自实际映射的静态只读入口，读取不会初始化片段管理器单例。它只属于本地窗口的动态读数，C 的运行快照协议保持原有字段范围。

数据来源：本地实现为 `MPPDataExchangeService.readResourceAudit()`，动态字段为 `sharedQueryContextPresent`。

## 派发前取消与查询终止

派发前取消使用真实的轻量片段上下文，规划开始标志保持为假。取消身份与正常派发共用原有并发映射，后续派发由重复身份检查拒绝。两个 volatile 引用只发布原映射，静态读取不初始化片段管理器单例。取消身份沿用原终态上下文的五分钟回收。

取消身份先发布，交换管理器随后取得资源创建锁。已由消费方创建的队列按真实生产方账户关闭，后续创建在相同锁内拒绝。只有交换清理和注销成功返回后，系统才发布真实取消终结证据。任一清理失败都保留异常及失败回执。

例如，消费方先建立生产者队列，生产者随后在派发前收到取消。完整回执必须证明队列关闭和账户注销，规划开始标志仍为假。后续规划、工厂或驱动事件出现时，观察完整性检查拒绝该记录。

查询终止先校验全部片段都属于真实查询，再逐片段执行取消。一个片段清理失败后，其余片段继续处理，原异常及附加异常保留。finally 只移除真实查询的共享上下文映射，活动片段继续持有原对象。独立片段取消保留共享映射。

本地终止与 RPC 使用同一查询入口。节点上未完成片段列表为空时，入口仍移除共享映射。本地清理失败后，终止器继续处理其他节点，再传播保存的异常。

数据来源：上下文与入口为 `FragmentInstanceContext` 和 `FragmentInstanceManager`。交换与终结观察为 `MPPDataExchangeManager` 和 `ResourceAuditManager`。调用方为 `SimpleQueryTerminator` 和 `DataNodeInternalRPCServiceImpl`。本地观察由 `MPPDataExchangeService` 提供。七个文件的方法与路径见 [B 取消生命周期接线](B_静态数据并行统一实现规划_20261031_实施版_复审修订.md#派发前取消与查询终止接线)。开始标志和终结对象为 `planningBegan` 与 `terminalEvidence`。

派发前取消的定向与真实服务记录保留原源码范围。最终源码的取消、准入失败和释放证据由 [资源机器验收](#资源机器验收) 对应中央状态。

数据来源：定向回执为 `/root/property-b-artifacts/B-cancel-before-dispatch-20261102-r1/final-focused-verdict.json`。静态审查为同目录的 `final-static-audit.json`。二者同时记录生产源码、编译类与既有测试身份。

## 多源派发与背压

多通道哈希交换使用实际片段依赖图。全部下游消费者确认后才派发共享源。普通树形片段继续使用既有路径，非法目标、重复身份和环均明确拒绝。

发送器持有当前待发送分区，并逐桶检查通道。阻塞期间禁止继续读子算子，恢复后每个分区恰好发送一次。普通轮询入口在显式哈希路由模式下不打开默认通道。

父 sink 独立决定自己的关闭和中止状态。即使所有子通道已经由消费者关闭，父 sink 仍须发出一次终态通知。子通道清理按 best-effort 完成并保存附加异常。

例如，两个源发送三十二桶时有六十四条交换边。先建齐三十二个消费者，再启动共享源，空桶结束通知才能到达已经存在的端点。

数据来源：派发与发送测试为 `FragmentDispatchDependencyGraphTest` 和 `HashPartitioningSinkOperatorTest`。父 sink 测试为 `ShuffleSinkHandleTest`。反向发送器验证为 `/root/property-d-artifacts/AD-hash-channel-reverse-20261102/`。真实拓扑与查询证据见 A–D 核查的双节点目录。

### B1 纯输入边界

B1 的三处生产实现缺陷已修补。大乘积保留为 long 值，空文件列表按元数据无效处理。生产生成器调用提取后的纯字节估计，累计和整数向上取整共用安全规则。

例如，十万台设备与三万个分区的中间乘积是三十亿，原合同要求输入并行度为八时最终目标为八。空文件列表须标记元数据无效，并保留原设备数作为估计。编译产物中的实际调用指令证明生成器已接入纯计算，该证据的范围为静态生产接线。

空扫描输入、单设备、重复输入分区、大乘积最终夹取和生产成本估计边界的专项断言已经通过统一定向。修补前构建、核心服务和一般资源按历史源码保存，最终源码的完整退出分别验收。其余服务输入按原 B6 矩阵逐项取证。

大乘积专项采用真实规划入口，构造十万设备和三万分区的有界元数据，成本输入为 null。预期只产生八个工作单元与八个桶，并核对覆盖范围。该选择保留目标并行度为八的原合同，避免生成三十亿个设备与分区组合。

数据来源：生产入口为 `ScanParallelPlanner.safeProduct` 与 `ScanParallelPlanner.estimateDopByBytes`。生产生成器入口为 `DataNodeTableOperatorGenerator.estimatePipelineNumByDataSize`。测试文件为 `plan/planner/ScanParallelPlannerTest.java`，既有乘法断言的期望值为 `3_000_000_000L`。退回与有序许可由 `serialReasonsRespectModeInputs` 和 `orderedModeUsesOrderingProofWithoutUnorderedFlag` 验证。算术与不可变由 `arithmeticRejectsNegativeAndIntegerOverflow` 和 `inputAndPlanAreImmutableSnapshots` 验证。

定向证据为 sc01 `/root/property-b-artifacts/AD-contracts-20261103-r1/focused-converged-09/root-focused-audit.json`。生产构建输入与各次原件的范围见 [A–D B1 修补证据](A-D_完整实现补全核查_20261102.md#b1-算术与成本估计修复) 和 [历史冻结证据](A-D_完整实现补全核查_20261102.md#历史冻结证据)。

补充检索范围为 `StaticParallelPlanAccountingTest` 和 `StaticParallelPlanDeterminismTest`。同时读取 `StaticScheduleInputValidityTest`。身份与时间分区的输入及断言核对包括 `ScanSourceIdentityIntegrationTest` 和 `DeviceTimePartitionMorselTest`。小规模夹取断言为 `StaticParallelPlanAccountingTest.everySourceBelongsToOneNonEmptyBucket`，输入是两个设备、十个分区与并行度八。成本列表为空、扫描并行度为一、仅一个分区分别具有对应测试，它们各自验证成本缺失、串行身份和单分区退回。

### B2 公共构建故障

实存测试通过生产构建器核对工厂、交换、登记数量及生效额度。设备与时间分区两条生产入口另有结构断言，真实交换身份也有独立核对。登记表测试覆盖父根接管及清理异常保留，驱动工厂失败测试覆盖其创建阶段。
