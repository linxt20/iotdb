## 七项阻塞逐条处理

1. 三种切分现状：设计新增“已在生产/本版新增”两节，列出 `DataNodeTableOperatorGenerator` 的五个记录点和三个开关。D2–D4 改为 planner 接线、身份和测试，不再把现有切分写成从零实现。
2. 两条 DOP 路径：设计和规划固定 planner 接管路径的优先级。`decideParallelScanPipelineNum` 只留给未接管旧路径，接管后不得覆盖 target；D0 保存两条调用链证据。
3. `ScanParallelPlanner` 无生产调用方：规划结论明确当前只有测试调用方，D2 是生产接线交付物；D0 manifest 记录该事实，不能把 API 存在当成生产闭环。
4. C 字段缺口：文档把 wall/rows/TsBlocks 等已建值字段与 CPU/bytes/ready/blocked 分开。后者没有来源时必须使用 `UNSUPPORTED_FIELD:<field>`，D 退出判据分为第一层可判定字段和 C 后续交付字段，禁止零填充。
5. 身份载体缺口：规划新增 `SourceKey`、`WorkUnit`、`Bucket`，并在 D2–D4 接入 FragmentInstanceContext、thrift（若 manifest 判定需跨 RPC）、exchange edge 和实际 driver 冻结计数；D0 明确字段编号/optional/混合版本策略，不再声称四类身份已经存在。
6. EXPLAIN ANALYZE 结果规则：设计正确性和规划 D6 均固定使用 EXPLAIN ANALYZE，明确剥离说明列与 CTE 说明行后再做业务结果多重集和 SHA 比较；普通查询无 final snapshot 时不得通过验收。
7. DOP 公式来源：删除无来源的 `cpuBudget` 项，公式统一为 `targetParallelism = min(configuredDop, workUnitCount, memoryBudgetCap)`；memory cap 的来源和无 reservation 的 UNBOUNDED 语义写入输入表与 D1 规划。统一 `configuredDop`/`targetParallelism` 命名。

## 其他审查意见处理

- 自然有序证明归因到 `DataNodeTableOperatorGenerator.isNaturallyMergeableDeviceScanOrder`；`TableDistributedPlanGenerator` 仅在确需传递 ordering property 时修改。
- fallback 词表保留生产 `NONE`、`PARALLEL_SCAN_NOT_SELECTED`，增加 canonical reason，并在 manifest 同时保存 raw/canonical 值。
- `driverTsBlocks` 统一为 `driverTsBlockCount`；统计 Drawer 明确为文本和 JSON 两个类。
- source ID 改为结构化 tuple 的 canonical 摘要，禁止从字符串后缀解析主键。
- driver 顺序固定为 fragment ID、`driverPipelineId` 数值、`driverTaskId` 字符串；字段 validity 改为按字段理由解析或新增字段查询方法。
- D6 定向命令覆盖 D1–D5 所有列出的测试类，并要求保存 effective POM、实际 `--add-opens`（含 `java.base/java.net`）、ANSI/去色日志和 Surefire XML。
- 两份文档均新增数据来源节，记录源码、协议、C 文档和当前基线；旧正文只在备份目录保留，不作为实施依据。
