## 查询执行的背景

一次查询在多个片段间共享队列时，资源对象、账目归属和关闭责任可能属于不同片段。验收必须能找到真正预留字节的账户，并能识别对象已经从映射移除但物理字节仍未释放的情况。扫描结构正确与资源清理正确都需要独立断言。

例如，上游片段 A 生产数据，下游 B 先创建队列，账户仍归 A。取消 B 后只看 B 的零预留无法证明 A 的队列已经释放。

## P1 处理

### P1-1 真实计数与首版生效额度

新稿明确真实计数首版只作诊断，生效额度保持各形态基线值。单扫描和纯 sink 形态的目标不高于基线，继续用较大值公式无法产生收紧收益。通用生成器存在计数复制和恢复，首版政策对这些组合也统一保持基线，避免把局部形态关系宣传成未经证明的全局定理。

例如，32 通道纯 sink 在指定预算下必须断言对象数 32、记账键数一、目标 125,703 字节，而生效额度仍为 4,022,509 字节。把 32 计成一的副本即使额度正确，也必须被独立计数与目标断言拒绝。

定位：[设计的分配目标与兼容下限](B_静态数据并行统一设计_20261031_第二轮.md#分配目标与兼容下限)，[规划的登记与基线额度快照](B_静态数据并行统一实现规划_20261031_第二轮.md#登记与基线额度快照)及[冻结与兼容退出条件](B_静态数据并行统一实现规划_20261031_第二轮.md#冻结与兼容退出条件)。

### P1-2 生产方记账与片段释放

新稿保留基线按上游生产片段记账的行为，两端关联与账户归属分别记录。下游可以先创建物理队列，账户仍使用上游的片段和源节点。B 补充读取与清理验证，账目迁移保持独立方案。

同一份非负快照中，query 总数为零且某片段非零不能同时成立。可验证反例采用强制注销先移除映射再抛异常，此时 getter 可以为零而池中仍保留物理字节。新稿增加注销前片段快照、原异常回执及池余量，禁止把映射缺失直接判成释放。

例如，队列保留 200,000 字节后强制注销，回执必须保存注销前非零值与 MemoryLeakException。之后 query 汇总为零也必须拒绝。正常取消需要全部关联片段为零并具有成功注销或未预留的明确回执。

定位：[设计的对象身份与内存记账](B_静态数据并行统一设计_20261031_第二轮.md#对象身份与内存记账)，[规划的片段读数与注销回执](B_静态数据并行统一实现规划_20261031_第二轮.md#片段读数与注销回执)。

### P1-3 轮询构造值与发送轨迹

新稿保持构造时轮询门限，禁止从规划后句柄额度反推。候选与冻结基线使用相同受控缓冲状态，逐步比较下标、发送序列和每通道计数。没有其他通道满足条件时保留当前下标。

例如，在堆为 2 GiB、查询线程为 32 的默认预算下，四通道门限为 3,016,881 字节。再有四条扫描流水线时，句柄最终额度为 804,501 字节，B 仍分别保持这两个数。测试必须能拒绝使用后者重新计算门限的副本。

定位：[设计的多通道轮询门限](B_静态数据并行统一设计_20261031_第二轮.md#多通道轮询门限)，[规划的轮询门限与轨迹](B_静态数据并行统一实现规划_20261031_第二轮.md#轮询门限与轨迹)。

### P1-4 两类查询的关闭槽

新稿同时覆盖 data 与 schema 两个执行入口，并要求复用创建与关闭助手。两类驱动都在销毁时结算关闭槽，未消费工厂也必须结算。数据来源补齐实际 latch 字段、初始化、递减与等待方法。

例如，schema 的三个工厂在第二个失败时，第一个驱动销毁结算一槽，失败与未消费工厂各结算一槽，最终为零。data 路径独立执行同样反例，不能互相替代。

定位：[设计的内存准入与失败清理](B_静态数据并行统一设计_20261031_第二轮.md#内存准入与失败清理)，[规划的驱动与工厂释放责任](B_静态数据并行统一实现规划_20261031_第二轮.md#驱动与工厂的释放责任)。

### P1-5 记账键的生产读取入口

新稿选定共享队列的不可变 getter 方案，明确列入生产修改范围。该入口返回创建时快照的字符串键，登记表直接读取，禁止依赖本地 source 和 sink 可为空的片段字段。

例如，四条流水线的包装字段为空时，队列返回的四条键仍必须非空。真实 reserve 后，测试将键逐项对应到内存池映射，并检查片段账户归属。

定位：[设计的对象身份与内存记账](B_静态数据并行统一设计_20261031_第二轮.md#对象身份与内存记账)，[规划的记账键读取与归属](B_静态数据并行统一实现规划_20261031_第二轮.md#记账键读取与归属)，拟新增入口为 `SharedTsBlockQueue.getMemoryReservationKey`。

### P1-6 通道级与查询级验收

B4 仅验证真实通道预留、释放、对象身份与额度，使用登记表、内存池和通道测试。32 桶查询成功与完整结果明确放到 B6，验收脚本先证明真实拓扑，再运行终态和结果比较。新增 Java 测试类仍为五个。

例如，通道发送一个真实大小介于诊断目标与基线额度之间的块，只能证明单块兼容。B6 必须另存该 32 桶查询的完整结果、真实 channel 和节点身份。普通 SQL 无法产生该拓扑时，必须显式组装隔离验收片段，禁止用较小桶数冒充。

定位：[规划的冻结与兼容退出条件](B_静态数据并行统一实现规划_20261031_第二轮.md#冻结与兼容退出条件)，[隔离服务与确定性输入](B_静态数据并行统一实现规划_20261031_第二轮.md#隔离服务与确定性输入)。

## P2 处理

四条 P2 分别对应数值前提、通道展开、关闭等待和配置恢复，新稿均给出可复核位置。

- P2-1：预算算例明确采用 2 GiB 堆与 32 查询线程，服务测试保存实际配置值。
- P2-2：七对象算例明确两个远端输出各一条 channel，多通道另给十一对象对照。
- P2-3：关闭清单补齐 allDriversClosed 字段和 releaseResourceWhenAllDriversAreClosed 等待点。
- P2-4：六节点运行前保存配置原字节、权限、SHA 和加载值，结束后恢复并比较。

例如，两个扫描开关从 false 开启为 true 后必须恢复 false，恢复文件的 SHA 必须与进入值一致。恢复失败独立报告，禁止只凭服务停止判为验收通过。

定位：设计的[对象身份与内存记账](B_静态数据并行统一设计_20261031_第二轮.md#对象身份与内存记账)、[分配目标与兼容下限](B_静态数据并行统一设计_20261031_第二轮.md#分配目标与兼容下限)和[内存准入与失败清理](B_静态数据并行统一设计_20261031_第二轮.md#内存准入与失败清理)，规划的[隔离服务与确定性输入](B_静态数据并行统一实现规划_20261031_第二轮.md#隔离服务与确定性输入)。
