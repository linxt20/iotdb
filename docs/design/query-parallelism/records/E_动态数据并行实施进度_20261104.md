## 三个冻结边界

算子生成前固定历史成员；每个源完成原估算后、创建自身子扫描资源前选择计划；整树完成后、原有单次准入前冻结源计划和真实归属。不同源顺序生成时，先前源可能已经创建资源，不能把第二个边界称为整片段无资源边界。

管理器清空 planning context 后，fragment context 继续持有冻结登记器。正常终态捕获、规划失败和 driver 创建失败均清除登记器；独立载荷保有不可变元数据。根 factory 加入后只核对 ID 集合，不发起第二次准入。

## 原指标复用与有界反馈

成本使用 C 已有的 driver 墙钟、输出行数和块数，没有另加一套计时器。片段使用短 ID、driver 使用完整 ID 时，差分规范化两种等价格式。行数、墙钟和块数在实际 C 适配器路径分别验证了 2→5、1000→2000 ns 和 2→4；这些是单元夹具值。计数回退或单侧缺失使整个区间失效；两侧都不支持时保持字段缺失。

动态分组每源最多 1024 个工作单元，重复设备及分区引用最多 1,048,576。十万设备成本输入使用映射查找，避免重复线性遍历。时间消费者在加权开关两档都使用同一有效分组；有序消费者逐设备建扫描，不把 1024 工作单元上限误用于实际设备扫描数。空工作桶有真实空流水线。

回执及源计划与历史响应共用有界库。完整拒绝回执按实际保留内容计费，并按本地到达时间过期。登记阶段限制元数据字节、配对数和工作引用数；超界清除可选反馈，保留执行计划及小型原因 `DYNAMIC_FEEDBACK_METADATA_BUDGET_EXCEEDED`。

响应本身仍受单条 4 MiB 的保留预算约束。旧冻结版的 1024 单元终态响应结构估计约 2.51 MiB，仅响应的三份保留估计已超过单条预算，因此没有进入普通反馈历史。这与登记阶段预算退回不同；不能因历史为空就声称没有执行动态分组。边界诊断另取原生终态响应，核对实际扫描算子、工作集合、准入及释放。

## 回执与账户

字段 43 `dynamicDecisions` 来自同一不可变决策回执，包含上下文、输入、前值和目标 DOP、估算状态、动作、原因、单元及桶数、输入反馈指纹和准入时账户。文本与 JSON 共用投影。`traceChecksum` 校验投影，`receiptChecksum` 标识完整回执；接收记录还需绑定独立源计划和原回执。C 的 `snapshotChecksum` 保持原运行指标、计划与配对校验域。

字段 44 `dynamicFeedbackDropReason` 传递登记预算退回原因。版本 1 携带新增 E 诊断字段时按版本不一致处理。

`AdmissionMemoryAccount` 只计原 `checkMemory` 的检查、申请、预留和释放。同池其他用途的申请不计入此账户。准入回执保存准入时快照，释放一般尚未发生；机器验收另取清理后的账户，检查次数、字节、注册表和活动执行均已收敛。

## 本轮发现并修复的两个缺陷

### 估算后的前值取错

原实现没有可信拒绝时，用本次静态桶数填写 `previousDop`，无法真实表达“上次四桶，本次实际估算上限二”。实际生产估算入口的回归断言期望 4、得到 2，原失败保留在 `previous-dop-regression-r1`。

现在前值来自冻结成员中最近一条成功完成成本与覆盖投影的样本。更新但不完整的样本不能覆盖它；没有合格样本时不捏造历史前值，沿用当前静态候选。可信拒绝仍具有更高优先级。实际规划夹具现验证 context=8、previous=4、input=2、target=2，以及真实重分组动作。夹具中的 192 MiB 是模拟文件元数据，不能替代机器实测文件大小。

### EXPLAIN 切片保留整个底层结果

旧实现按逻辑字节检查结果切片，但交换层按 retained-memory 计费，切片仍持有整块底层数组。1024 单元的文本诊断暴露了该问题。现有 `ExplainAnalyzeOperatorTest.largeTextResultIsBatchedWithoutChangingAnyRows` 增加 retained-size 断言后失败，原件保留在 `explain-retained-regression-r1`。

修复后复制所选行，按实际保留内存收紧分块；单行超界仍明确失败。测试同时检查完整行序列、逻辑大小、保留大小和关闭行为。最终边界诊断采用原生 JSON 格式以控制文本补齐带来的输出规模；完整业务结果仍来自普通 SQL。

- 单、双节点各三轮普通业务对照通过完整 typed 多重集、SHA 和有序全序列。独立核查覆盖 68 次查询、124 个源记录，使用实际节点、fragment、源、bucket 及 work ID，完整核对设备范围。
- 单、双节点真实小容量池取得 4→3→2→1 的原生拒绝与降级证据，24 份资源快照通过。故意失败的压力查询不计为业务通过。
- 时间加权开关两档及有序 16 设备单桶均有三轮普通查询完整结果。独立原生响应核查证实 1024 个时间扫描算子及 1024 个唯一工作单元归同桶；旧版诊断查询的交换失败另列，不计为成功。

## 最终版机器验收

本节只对应最终 r4 冻结版与 `production-r29`。实际执行源及 JAR 与前述清单一致，不使用较早版本替代。

- 单、双 DataNode 分别完成三轮四类普通查询的 typed 完整多重集、SHA 和有序全序列对照。每个全扫描为 4608 行。独立核查覆盖 68 次查询、124 个唯一源记录，使用实际节点、fragment、源、bucket 和 work ID，完整核对设备范围。
- 两种拓扑都真实出现 KEEP_STATIC、REBALANCE_NEXT_FRAGMENT、REDUCE_DOP 和 SERIAL_FALLBACK。24 份原生拒绝与释放快照通过；压力失败仍独立列为拒绝证据。
- 时间加权开关两档分别执行 1024 个子扫描并归同桶，普通结果及原生 JSON EXPLAIN 均连续三轮成功。有序场景的 16 个设备归同桶，512 行完整序列与对照相同。每组拓扑有两个 DataNode，边界 fixture 的单个 region 只在其中一个扫描节点上；它不冒充双源扫描证明。
- 两侧实际 region 文件均从 432563369 B 降至 199642283 B。配置上下文为 8，原估算输入为 2，候选的前值 4 绑定到独立保存的四桶历史，REBALANCE 的最终目标为 2。关闭 E 的对照保留原生 C 快照，实际规划二桶、三个 driver。三轮 24000 行完整结果一致。文件切换使用已说明的原生卸载接口，原 padding 文件全部留档。
- CHECK_DISABLED 与 HIGHEST_PRIORITY_ZERO_RESERVATION 均有明确原生原因、检查次数和零预留账户；结束后全池额度恢复。124 份普通受管源的原生 B 对象数、唯一内存键数和名义份额字段均存在且为正值，零准入例外不被用来放行缺失的 B 资源统计。
- 169 份运行快照的已加载类来源匹配最终 server/Thrift JAR，JVM 库身份已保存，47 份隔离进程记录均确认服务停止。

## 最终完整套件与收集器恢复

标准 DataNode 全量为 840 类、5327 个唯一测试，失败和错误均为零，跳过 50 项。配置排除的 24 个 subscription 类单列，不算作跳过或通过。源码未变，发行包的 4251 个 server class 与被测 target 完全一致。

原收集脚本读取刚退出进程的 `/proc` 时遇到 ESRCH，测试 Maven 仍继续运行。恢复过程没有重跑任何测试，也没有修改生产或测试字节码。真实 Maven 退出码 0 由内核 PTRACE_EVENT_EXIT/GETEVENTMSG 捕获，不是从 BUILD SUCCESS 文本推断。

轮询间隙没有被伪装成已采集的进程记录。实际保留了 568 个 Surefire fork 的 `/proc` 元数据；全部 840 份 XML 的真实 JVM 启动属性分别绑定原 booter、provider 和 system-properties 文件，完整类加载日志证明所有预期测试类的来源。两次架构检查子 JVM 主动清除了日志环境变量，但在原 XML 自报实际 4 GiB 堆及加载路径，两项父 JUnit 检查均成功。独立审计使用这些原始证据，不编造缺失 PID 或 argv。

最初因收集证据缺项而标为 FAIL 的汇总及原异常全部保留。最终核对结果使用 `verdict-recovered-r2.json` 与 `full-independent-audit-resumed-r2`，不能误读旧汇总为测试失败。
