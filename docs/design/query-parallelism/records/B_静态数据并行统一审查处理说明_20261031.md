# B 静态数据并行统一审查处理说明

目的：供 sxing 和复审者逐项核对 B 审查意见在新设计与实现规划中的处理位置、验收出口及待实施边界。

摘要：独立审查覆盖两条 P0、八条 P1 和五条 P2。本文把各条意见对应到新稿中的具体章节，并给出接受或澄清的依据。资源额度和归零观测涉及实际内存池及生命周期，本文区分源码事实、设计决定与尚未执行的测试。

结论：十五条意见均有文档处理与测试出口，B 两份新稿等待独立复审。资源方案采用基线兼容下限，并把通道预留、轮询门限和内存池记账分开。工程 HEAD 与工作区保持原样，本轮交付只证明文档修订和源码核查完成。

未决问题：性能倍数、生产哈希连接和 CPN 正文范围等待 sxing 决定。兼容下限、本地验收接口及轮询门限的方案决定提交 sxing 复审，B 实施仍等待文档审核。

## 查询执行的背景

扫描拆成多个分支后，查询必须保持完整读取和原排序结果。建立执行对象期间失败时，系统必须释放已经建立的资源。文档必须把何时登记、谁关闭、用什么证据证明释放写成实施者可以执行的步骤。

例如，第三个分支建立交换源失败时，前两条分支和第三条已经建立的汇与队列都需要关闭。若等全部构建完成再登记，清理就无法定位这些对象。

数据来源：[独立审查报告](B_静态数据并行统一文档审查_20261028.md)共 378 行，MD5 为 `31b6cb234ca3b12fd89ae8b6bab6985e`，核查基线为 sc01 `/root/iotdb` 的 `feat/next-p0`，提交 `8d5d9c6a2c838e42f21be9ebd3278151fb75c520`。

## 优先级与阅读入口

本文沿用审查报告编号，逐项给出新稿入口。P0 表示实施前必须解决的方向或正确性问题，P1 表示重要行为或验证缺口，P2 表示定位与表述问题。文档处理完成与实现通过属于两种状态。

新设计规定行为和范围，新规划规定文件、步骤和退出条件。原审查对象与原报告保留原文，新稿使用独立日期文件名。全部拟新增类、JMX 操作和测试仍属于待实施项。

数据来源：[新设计](B_静态数据并行统一设计_20261031.md)与[新实现规划](B_静态数据并行统一实现规划_20261031.md)，逐文件身份见 `/root/property-b-artifacts/B-docs-revision-20261031-01/source-audit.json`。

## P0 处理

### P0-1 创建与登记顺序

新稿采用每次创建后立即登记的顺序，并把队列工厂内部的登记列为明确修改位置。资源关闭根、端点通知与结构记录分别处理。工厂内部创建队列后、创建 sink 之前发生异常时，登记表已经拥有队列。

验收分别在队列创建前、队列创建后和 source 创建时注入失败。例如，第三组 source 失败后，前三组已建对象均在登记表内，各独立关闭根与各对象的有效终态转换必须为一次。通知按实际对象身份核对，包装数量单独记录。

定位：[设计的公共流水线构建](B_静态数据并行统一设计_20261031.md#公共流水线构建)，[规划的 B2 设备与时间分区公共构建](B_静态数据并行统一实现规划_20261031.md#b2-设备与时间分区公共构建)。

### P0-2 单块合法域与兼容额度

新稿接受逐对象不低于基线最终额度的兼容要求。真实数量计算分配目标，基线额度提供保守下限，最终申请取两者较大值。该下限同时覆盖基线准许的全部单块申请，首版无需依赖未知算子的严格最大块估计。

例如，32 通道反例中的目标为 125,703 字节，下限为 4,022,509 字节，最终额度保持后者。163,840 字节的单块仍通过内存池校验。无扫描拆分的纯 sink 查询同样纳入真实发送与基线比较。

基线内存池按 query、片段与 planNodeId 累计，另有全池总量约束。兼容下限可能使对象额度之和超过片段配置预算，因此 B 的保证为逐对象兼容、真实计数与现有全池约束。新稿明确保留这个边界，严格片段总量配额需要独立方案。

定位：[设计的分配目标与兼容下限](B_静态数据并行统一设计_20261031.md#分配目标与兼容下限)，[规划的冻结与兼容退出条件](B_静态数据并行统一实现规划_20261031.md#冻结与兼容退出条件)。

## P1 处理

### P1-1 算术提取范围

B1 明确提取区域文件大小估计、目标分支夹取和设备数乘分区数的纯部分，元数据读取留在原侧。已有分区加权路径的饱和相加与负值退回继续保留。负大小必须输出元数据无效原因。

例如，100,000 与 30,000 相乘得到 3,000,000,000，先用 long 计算，再按 DOP 为八夹取。测试必须定位到目标乘法的提取后函数，避免只测试权重分组却声称验证了该溢出。

定位：[设计的配置与估计边界](B_静态数据并行统一设计_20261031.md#配置与估计边界)，[规划的 B1 纯拆分计算](B_静态数据并行统一实现规划_20261031.md#b1-纯拆分计算)。

### P1-2 构建与渲染回归

B0 定向清单由六类组成，加入已有构建和渲染测试。B4 核对局部计数的原断言与真实对象计数，B5 核对既有物理编号及静态字段。B6 必须逐类检查 XML 存在，五个新增测试类另行纳入完整清单。

例如，完整测试清单包含渲染类但缺少它的报告时，覆盖检查必须失败，即使其他类都通过。

定位：[规划的 B0 基线与执行身份](B_静态数据并行统一实现规划_20261031.md#b0-基线与执行身份)、[登记与基线额度快照](B_静态数据并行统一实现规划_20261031.md#登记与基线额度快照)、[静态信息与已有采集点](B_静态数据并行统一实现规划_20261031.md#静态信息与已有采集点)。

### P1-3 并发收紧入口

队列字段、读取与更新采用同一原子数，两个本地包装层直接委托，移除读后判断。三类入口分别验证较小值与读可见性。队列 setter 若已执行真正的原子 min，包装层的陈旧读本身无法再次放宽它，新稿仍采用直接委托以减少分散判断。

例如，4 MiB 已写入后再调用原子 min 更新 8 MiB，结果仍为 4 MiB。测试也会故意改回原始赋值，确保双线程断言识别放宽。

定位：[设计的限额应用与并发](B_静态数据并行统一设计_20261031.md#限额应用与并发)，[规划的原子收紧与读可见性](B_静态数据并行统一实现规划_20261031.md#原子收紧与读可见性)。

### P1-4 轮询门限与硬预留

新稿把派生门限纳入冻结，采用每通道门限并在发布通道额度后发布门限。源码中的该门限仅属于 SIMPLE_ROUND_ROBIN 的选路条件，PLAIN 和哈希显式选桶采用各自路由。预留额度继续由 channel 和内存池执行。

例如，基线选路门限 1.5 MiB、通道额度 1 MiB 时，冻结选路门限为 1 MiB。测试必须读取真实策略值，另测 channel 预留，避免把选路条件当作实际内存申请校验。

定位：[设计的多通道轮询门限](B_静态数据并行统一设计_20261031.md#多通道轮询门限)，[规划的轮询门限冻结](B_静态数据并行统一实现规划_20261031.md#轮询门限冻结)。

### P1-5 非法单块与合法等待

新稿明确区分单块超限的 IllegalArgumentException 与累计额度不足的 future 等待。最高优先级零预留豁免发生在单块校验之后。正常 B 配置由兼容下限保护，超限异常用直接内存池测试及隔离故障副本验证。

例如，一次申请超过额度时必须抛异常并归零。单块低于额度但已有累计预留时，必须等待消费释放，取消时 future 必须完成或取消。

定位：[设计的申请异常与等待](B_静态数据并行统一设计_20261031.md#申请异常与等待)，[规划的全局算子内存与异常出口](B_静态数据并行统一实现规划_20261031.md#全局算子内存与异常出口)。

### P1-6 输入快照字段

新稿显式列出无序并行许可位、溢写状态、输入 DOP 及采集时刻。输入在创建子上下文前冻结，按入口模式决定是否检查无序许可位。有序路径保留共同基础资格与排序证明。

例如，DOP 为一与存在溢写句柄两条输入均输出串行。有序模式许可位为假但排序证明成立时，仍允许原有有序并行。

定位：[设计的拆分计算与不可变描述](B_静态数据并行统一设计_20261031.md#拆分计算与不可变描述)，[规划的新增描述与计算类](B_静态数据并行统一实现规划_20261031.md#新增描述与计算类)。

### P1-7 配置属性名

新稿使用配置加载器实际读取的查询并行度属性，其余四个开关保持原键。核查脚本必须逐字检查五个键都存在于配置加载源码。

例如，验收配置把查询并行度设为一后，执行身份记录必须同时显示加载后数值为一。仅在配置文件中出现该字符串不能证明它生效。

定位：[设计的配置与估计边界](B_静态数据并行统一设计_20261031.md#配置与估计边界)，真实键名为 `degree_of_query_parallelism`。

### P1-8 资源释放证据

新稿提出有界本地 JMX 验收窗口，由实际生命周期报告驱动、队列、工厂、端点与 future，内存数值复用现有接口。统计条目与注销日志用于辅助定位，实时数量由明确的新增接口提供。窗口过期、容量溢出或无法关联必须标为证据不完整。

验收记录空闲、运行中与终态三份 JSON。例如，运行中五驱动四队列在取消后回到空闲零值，query 交换预留为零，全局字节仅在隔离环境与空闲基线比较。运行中非零记录同时证明资源确实分配过。

这项接口限定为本地资源验收，C 继续负责运行指标快照与跨节点协议。B5 先实现观测入口，B6 才运行依赖该入口的服务验收。

定位：[规划的本地资源验收观测](B_静态数据并行统一实现规划_20261031.md#本地资源验收观测)，其中列出 MBean 方法、字段、容量、生命周期接入点及测试。

## P2 处理

P2 五条均已落到新稿文字与定位约定，代码范围由相应 P0、P1 的方案决定。

- P2-1：源码定位统一采用方法名与固定 SHA，移除易变基线行号。
- P2-2：新增可运行测试类数量统一为五个，已有扩展类另计。
- P2-3：sink 登记定位为 visitIdentitySink、visitShuffleSink 与实际句柄工厂方法。
- P2-4：空设备列表明确沿用串行 TableScanOperator。
- P2-5：区域文件对 DOP 的估计与分区大小加权分组分别定义，并列出各自配置键。

数据来源：新稿对应[已有执行路径](B_静态数据并行统一设计_20261031.md#a-发布基线的执行路径)、[拆分输入](B_静态数据并行统一设计_20261031.md#拆分计算与不可变描述)、[配置边界](B_静态数据并行统一设计_20261031.md#配置与估计边界)及规划 B4、B6。

## 生命周期接口与实施状态

新稿还明确提前关闭驱动所需的关闭计数初始化。基线在所有驱动创建后才初始化 latch，而驱动销毁会递减它。B 在创建循环前按工厂数量建立关闭槽，由已建驱动和未消费工厂分别幂等结算。

例如，三个工厂的第二个失败时，第一个驱动销毁结算一槽，第二与第三工厂各结算一槽，最终剩余为零。取消与构造返回交错的样例必须用可控屏障验证。

本轮只做源码、配置、符号、文档链接和审查覆盖核查。B 的五个新测试类、真实发送、JMX 接口、完整模块与双节点测试均待实施。A 的已有通过证据仅作为固定基线保留。

数据来源：[设计的内存准入与失败清理](B_静态数据并行统一设计_20261031.md#内存准入与失败清理)，[规划的驱动与工厂释放责任](B_静态数据并行统一实现规划_20261031.md#驱动与工厂的释放责任)，核查与同步记录保存于 `/root/property-b-artifacts/B-docs-revision-20261031-01/`。
