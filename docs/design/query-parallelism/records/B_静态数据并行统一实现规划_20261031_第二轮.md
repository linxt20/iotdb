# B 静态数据并行统一实现规划

目的：为实施者规定 B 的文件级修改、依赖顺序与测试退出条件，供 sxing 在实施前审核范围和工期。

摘要：B 需要把已有三条扫描构建路径的公共步骤集中到统一入口。资源治理还涉及本地队列、远端通道、完整内存估计和驱动创建失败后的清理。本文将工作分为冻结基线、纯拆分计算、公共构建、资源准入和真实执行验收。每一步都列出代码落点与可验证产物。

结论：B 按 B0 至 B6 顺序实施，每一步关闭退出条件后再进入下一步，预计单人六至九个工作日。首版沿用已有扫描资格、DOP 输入和静态分组配置，并补齐真实计数断言、基线额度保持、轮询轨迹对比与两类驱动的异常释放。本文为待审规划，B 生产代码、单元测试和真实运行均尚未实施。

未决问题：性能倍数、生产哈希连接和 CPN 正文范围均等待 sxing 决定。基线额度保持、真实计数只记录及本地验收接口作为本稿方案等待 sxing 复审，B 按[设计范围](B_静态数据并行统一设计_20261031_第二轮.md#术语与范围)实施。

## 查询拆分的实施背景

扫描分支增加后，系统必须继续读取同一批数据，并在需要时保持整体排序。实施者还必须证明资源不足或创建中断时，已经建立的执行对象都能释放。只移动代码或只比较最终行数，都不足以完成这项工作。

例如，三条分支中第二条创建失败时，第一条已经成功的驱动也必须关闭。若只关闭失败分支自身，查询虽报告失败，第一条驱动的队列仍可能保留内存。B 必须把这些责任写入同一构建流程并验证。

数据来源：代码基线为 sc01 `/root/iotdb` 的 `feat/next-p0`，提交 `8d5d9c6a2c838e42f21be9ebd3278151fb75c520`，行为约束由[B 统一设计](B_静态数据并行统一设计_20261031_第二轮.md)定义。

## B1 纯拆分计算

B1 必须先完成不可变描述与独立计算测试，再连接真实算子。输入使用设备快照序号、有序分区列表、可选权重和配置快照。输出包含模式、实际组、输入与目标并行度、排序证明、过滤融合标记和原因。

### 新增描述与计算类

描述构造函数必须复制列表与映射，拒绝重复分区和非法组，禁止保存可变上下文。输入类型必须显式携带无序并行许可位、是否溢写和输入 DOP，取值时刻为扫描入口创建子上下文之前。有序模式采用共同基础条件与排序证明，无序和直接过滤融合额外检查许可位。串行退回必须在建立任何子上下文前决定。

例如，设备数为一、分区数为三、DOP 为四，输出仍为串行。设备数为六、分区数为三、DOP 为四，输出的分组按设计的时间优先公式产生三条工作单元，覆盖预期十八个组合。

区域文件列表与分区大小的元数据采集保留在生成器与 TsFileManager 一侧，纯计算接收文件大小快照及独立的完整性状态。区域文件估计中的负大小、累加、整数向上取整，以及目标分支的设备数乘分区数均归 B1。缺失数据改用等数量分组，完整权重按确定顺序分配。计数乘法、累加和向上取整必须按[配置与估计边界](B_静态数据并行统一设计_20261031_第二轮.md#配置与估计边界)处理。

退出条件：纯测试覆盖空输入、单设备、DOP 为一、溢写、许可位按模式区分、上限夹取、重复分区、稳定同值、无元数据与描述不可变。负大小必须输出元数据无效原因，禁止把负大小解释成小区域。接近 long 上限的累计保持饱和，整数向上取整必须经过目标上限夹取后才转 int。

例如，100,000 台设备与 30,000 个分区的中间乘积为 3,000,000,000，输入 DOP 为八时，最终目标为八。测试仅传入计数与少量代表数据，禁止构造三十亿个组合。每个算术反例必须关联提取前方法和提取后被测函数。

修改位置与测试：新增 `plan/planner/ScanParallelPlan.java` 和 `ScanParallelPlanner.java`，新增 `plan/planner/ScanParallelPlannerTest.java`，从 `DataNodeTableOperatorGenerator.java` 提取 `partitionIntoGroups`、权重分配、`estimatePipelineNumByDataSize`、`decideParallelScanPipelineNum` 的纯部分，以及 `constructParallelDeviceTpMorselScan` 的目标乘法。区域元数据读取仍在原侧，已有加权路径的饱和与负值检查保持合同，入口暂以适配器保留。

### 时间范围与语义复制

时间范围必须按运行时真实分区间隔与时间精度计算，源查询条件始终保留。实现者必须核查全局时间工具与目标数据库分区配置的绑定，绑定无法证明时在建资源前退回原扫描。边界预期必须独立于被测助手计算。

例如，输入时间区间包含负一、零和分区边界，测试必须逐点比较是否落入相应子扫描。针对 long 最大值，测试必须证明可读数据域内没有遗漏，无法表示的半开范围走已定义的边界退回原因。

退出条件：范围测试覆盖负分区、时间别名、原条件相交、多分区逻辑或、极值和不支持的配置，克隆前后原节点字段逐项一致。例如，子扫描缩小为两台设备后，原扫描仍包含六台设备，TopK 关联 ID 保持原值。

修改位置与测试：`DataNodeTableOperatorGenerator.java` 的 `requireTimeColumnName`、`buildTimePartitionRangePredicate`、`cloneSubScanNode` 及参数构造入口，扩展 `plan/planner/DeviceTimePartitionMorselTest.java`，独立纯范围测试可以加入 `ScanParallelPlannerTest.java`。

## B2 设备与时间分区公共构建

B2 必须把两条无序路径接入公共构建器，保持父 Collect、参数构造和源登记语义。B2 同时建立资源登记表的规划清理部分，B4 再补齐额度冻结。生成器负责采集输入与构造具体算子，构建器负责接线与所有权。每创建一个资源立即登记，禁止先批量构建再补登记。

公共构建器接收不可变描述和构造回调，逐组生成子上下文、克隆扫描、参数、扫描算子及可选过滤根。扫描构造返回即登记关闭根，sink 工厂内部先登记队列，再登记 sink，source 返回即登记端点。随后才建立 ExchangeOperator、估计与工厂，并分别登记额度身份、估计父关系和未消费责任。工厂加入共享列表必须晚于它的责任登记。物理 ID 使用源节点与组序号，整数流水线 ID 继续由上下文共享分配。

例如，六个工作单元必须对应六个不同工厂、六个队列和六个交换源。每个估计必须关联正确父节点，根工厂仍由本地规划器最后追加。两源同组序号的物理扫描 ID 必须保持不同。

规划登记表必须提供独立关闭根登记与父子挂接接口。父子挂接完成后，子树关闭责任转移到父根，独立关闭集合只保留父根。端点中止项保持独立且幂等。

例如，两个扫描挂入组内合并后，清理只调用合并根的递归关闭。测试应当记录各算子的关闭次数，禁止以所有算子都至少关闭一次代替恰当的所有权验证。

过滤融合继续调用原执行构造，单独保留直接子扫描、无 diff 等限制。普通投影仍使用既有访问入口。所有构建回调必须传递原克隆语义字段，禁止以手写最小构造替代完整 clone。

退出条件：已有设备与工作单元测试通过，构建断言覆盖工厂、sink/source、源登记、父估计、唯一 ID 和原节点字段。故障分别注入队列创建前、队列已建而 sink 构造失败、sink 已建而 source 失败三个位置。

例如，第三组在 source 建立处失败时，前三组已经存在的对象必须全部出现在登记记录中。独立扫描根各递归关闭一次，sink 与队列各只有一次有效终态转换，所有回调通知按对象身份核对。结构记录移除数量单独核对，禁止把工厂项与队列通知混成同一个总数。

修改位置与测试：新增 `plan/planner/LocalScanPipelineBuilder.java` 与 `LocalScanPipelineBuilderTest.java`，建立 `LocalExecutionResourceRegistry.java` 的清理与子上下文共享接口，修改 `DataNodeTableOperatorGenerator.java` 的 `constructParallelDeviceScan`、`constructParallelDeviceTpMorselScan`、`visitFilter`，保留 `constructTransparentMorselFilter` 的执行表达式入口，扩展 `DeviceTableScanParallelPipelineTest.java` 与 `DeviceTimePartitionMorselTest.java`，修改 `execution/exchange/MPPDataExchangeManager.createLocalSinkChannelForPipeline` 增加接受登记回调的生产重载，原签名委托新实现以保留既有调用方。

## B3 有序构建与属性交接

B3 必须在同一构建器中保留每设备扫描、组内合并与组间合并三层对象关系。共用的是流水线接线，单设备扫描和比较器继续由有序模式的回调构造。有序入口继续使用忽略无序许可位的共同基础资格，并额外证明完整自然顺序。

例如，四台设备被分为两组时，每组包含两台独立扫描，并通过组内合并输出有序流，根再合并两条流。相同时间戳按完整排序条件比较，null 顺序与升降序必须继承原排序定义。

许可位为假但排序证明成立的样例必须继续形成有序并行。相同许可位为假时，无序扫描和直接过滤融合必须使用原入口。两条断言共同检查资格适配，避免共用助手扩大或缩小已有能力。

退出条件：两层合并结构、完整输出序列、反向扫描、标签加时间、相同键与 null、字段排序退回、时间位于非末位退回、列映射缺失退回均有断言，A 的属性合同与快照回归通过。

修改位置与测试：`DataNodeTableOperatorGenerator.java` 的 `visitSort`、`visitStreamSort`、自然顺序守卫和有序构建方法接入 `LocalScanPipelineBuilder.java`，新增 `plan/planner/OrderedScanPipelineContractTest.java`，沿用 `DeviceTableScanParallelPipelineTest.java` 的已有有序样例，分布式属性组件保持 A 的合同。

## B4 真实资源计数与内存准入

B4 必须把真实对象计数、基线额度和既有全池记账关联起来，首版配额策略保持基线，真实计数只生成诊断目标。上下文的 data、schema 构造初始化登记表，子上下文共享同一实例。原局部计数的 add、set、保存和恢复继续作为原算法输入。

### 登记与基线额度快照

登记表按真实队列、远端 source 与远端 channel 去重，并保存完整 query、片段、planNodeId 记账键。同节点跨片段队列按上游生产片段记账，接收方先分配队列也保留这个归属。各个原 setter 调用点必须把作用对象和原额度交给登记表，普通本地 source 的空 setter 也必须显式记录为无生效写入。最终 ExchangeOperator 遍历产生的基线收紧仍需计入独立快照。

B0 先冻结 A 基线的完整额度轨迹，B4 用同形态记录比较真实计数与兼容下限。纯 sink、纯 source、两源合并、多桶输出、本地跨片段、树模型与 schema 都必须有记录。基线登记回调与新 getter 的键必须一致，接收方和生产方先创建两种顺序都要覆盖。字段缺失或类型未适配时，规划必须明确失败。

退出条件：每个形态必须直接断言登记表对象身份集合、真实数量、记账键集合和诊断分配目标。32 桶纯 sink 必须有 32 个 channel 身份、一个上游记账键，禁止仅比较最终额度。四条本地扫描的包装片段字段为空时，队列 getter 仍必须给出四个与真实预留一致的非空键。

例如，采用设计的 2 GiB 堆与 32 查询线程配置，32 桶的诊断目标必须为 125,703 字节。把它误计为一的隔离副本会得到 4,022,509 字节，即使生效额度保持正确，目标断言也必须失败。

修改位置与测试：完善 `plan/planner/LocalExecutionResourceRegistry.java`，新增 `LocalExecutionResourceRegistryTest.java`，修改 `LocalExecutionPlanContext` 的三个构造、`addExchangeOperator`、原额度计算及最终遍历。通用侧接入 `OperatorTreeGenerator.visitExchange`、`visitIdentitySink`、`visitShuffleSink` 和创建子流水线的交换路径，表模型侧接入 `DataNodeTableOperatorGenerator.visitTableExchange`、`visitIdentitySink`、`visitShuffleSink`，sink 由 `MPPDataExchangeManager.createShuffleSinkHandle` 创建。

### 冻结与兼容退出条件

冻结必须保持各对象的基线最终额度，并单独保存按真实数量计算的诊断目标。原额度应用改为记录加冻结，诊断目标保持只读用途。跨片段队列遵守原子收紧，最终值必须等于双方基线额度的较小值。

例如，堆为 2 GiB、查询线程数为 32，默认片段预算为 4,022,509 字节。32 通道的诊断目标为 125,703 字节，基线与候选生效额度均为 4,022,509 字节。B4 必须直接读取这三个字段并分别断言。

通道级退出条件由真实 SinkChannel、LocalSinkChannel 与 MemoryPool 单元测试承载。构造大小介于目标与生效额度之间的 TsBlock，保存实际 getSizeInBytes，发送必须通过单块校验、消费后释放。纯 MemoryPool 参数测试另外使用 163,840 字节反例，最高优先级和普通路径分别验证。

查询成功与完整结果属于 B6 的隔离服务验收，承载入口为 run-two-datanode.py 的 32 桶纯 sink 查询用例。B4 只要求真实单块预留与释放、额度和身份正确，禁止把通道测试通过写成查询通过。该查询入口不新增 Java 测试类，规划新增类总数仍为五个。

其他退出条件覆盖零对象、非正预算、零目标只记录、重复冻结拒绝、跨片段两侧冻结顺序与无扫描形态。兼容断言必须核对最终申请额度等于基线，计数断言独立核对全部对象与记账键，防止一项掩盖另一项错误。

例如，四通道纯 sink 和三字节预算产生零字节目标，生效额度保持三字节。已预留两字节时再申请两字节，累计不足进入等待，并在释放后完成。单块超过三字节属于异常路径。

### 驱动与工厂的释放责任

工厂必须提供生产可用的未消费资源关闭入口，成功创建驱动后把责任移交给驱动。片段管理器必须使用显式创建循环，保留已建驱动列表，并在任意失败时逐个关闭。最后一个根工厂的顺序继续保留。

工厂必须区分未消费、创建中、已移交和已关闭四种状态，并保护创建与关闭的状态转换。创建循环开始前按工厂数量初始化关闭槽，成功驱动销毁与未消费工厂关闭各自通过幂等状态完成一个槽。当前失败工厂与剩余工厂都必须结算，避免提前关闭触发空 latch 或永久等待。创建循环必须在移交前检查片段终态，取消发生在构造返回之后时，创建循环负责关闭尚未移交的驱动。工厂状态、登记表与创建列表只能有一个有效关闭责任方。

例如，用屏障把第二个工厂暂停在驱动构造返回与移交之间，再发送取消。解除屏障后，第二个驱动必须关闭，第三个工厂必须保持未消费并释放资源，禁止继续提交调度。

例如，第二个工厂失败时，第一个驱动和第三个未消费工厂都必须释放。第一次关闭抛异常后，清理循环仍必须处理剩余对象，并保留原异常及 suppressed 异常。工厂和登记表只释放自己仍拥有的对象。

### 本地资源验收观测

资源归零必须由实际生命周期、真实片段账目和真实内存池读数共同证明。登记表记录每个片段的未消费工厂、已建未关闭驱动、物理队列关联、端点和待完成 future。对象计数只在实际关闭或 abort 完成后减少，移交责任与清空集合都不能冒充释放。

##### 记账键读取与归属

共享队列新增不可变记账键 getter，返回创建时固定的查询、生产片段与源计划节点。接收方先创建同节点队列也必须得到上游生产片段的键。首版保留基线归属，通过生产片段与消费片段的关系记录定位清理，禁止把同一份预留分摊记到两侧。

例如，生产片段 A 向消费片段 B 写入 200,000 字节，预留归于 A 的键，B 的账户可以是零。验收必须读取 A 和 B 的片段数据，并核对队列令牌与 A 的键对应，不能只查看被取消的 B。

修改位置与测试：`SharedTsBlockQueue` 新增嵌套 `MemoryReservationKey` 与生产 getter `getMemoryReservationKey`，构造时复制真实字符串。`LocalExecutionResourceRegistry` 使用这个 getter，`SharedTsBlockQueueTest.java` 和 `LocalExecutionResourceRegistryTest.java` 验证本地包装标识为空、生产方先建与接收方先建三种形态，实际 reserve 后核对映射。

##### 片段读数与注销回执

内存池拟新增片段级只读快照，返回映射是否存在、按 planNodeId 的预留和片段总字节。查询级总数在终态静止点用同一份账户快照求和，必须等于所有片段数之和。运行中的非同步读取只作为运行证明，禁止用不同时间的读数构造一致性断言。

例如，A 有 200,000 字节、B 为零，同一份非负快照的 query 总数必须为 200,000 字节。query 为零且 A 非零在这种快照里无法成立。故障反例改用映射删除后 getter 返回零，但池中物理字节仍未释放。

在每次注销调用前，验收窗口必须保存片段账户与资源状态，调用后保存成功或原异常。强制注销遇到非零账目时，基线会先删除映射再抛 MemoryLeakException，映射消失必须保留这一失败回执。非强制注销遇到非零值会保留条目，等待端点释放后还必须有成功的最终核对。

例如，故障副本保留队列中的 200,000 字节并执行强制注销。随后 query 与片段 getter 都可能返回零，但注销前片段记录为 200,000，故障计数非零，池剩余未恢复。验收必须拒绝该结果，不能用最终映射缺失覆盖已经观察到的泄漏。

缺失映射只有在保存了正常零预留注销回执时才能解释为已清理。全程没有调用 reserve 的空输入可以用明确的未预留回执通过。除此之外，缺失回执、窗口过期、残留字节或注销异常一律标记证据不完整或失败。

修改位置与接口：拟新增 `MemoryPool.snapshotFragmentReservations(queryId, fragmentInstanceId)`，嵌套快照包含 `present`、`byPlanNode` 与 `fragmentReservedBytes`，供本地验收读取。`MPPDataExchangeManager.deRegisterFragmentInstanceFromMemoryPool` 在调用实际注销前后向窗口写回执，原 `MemoryLeakException` 必须继续传播。`MemoryPool.deRegisterFragmentInstanceFromQueryMemoryMap` 保留原记账归属与校验行为。

测试与边界：`MemoryPoolTest.java` 验证片段读取、非强制保留和强制删除后仍抛异常，登记表测试验证 query 零但泄漏回执非零时拒绝。生产协议不在 B 改为消费方记账，B 只补观察与清理顺序，任何另行改变归属的需求单独审查。

##### 有界本地观测接口

B5 拟提供本地 JMX 验收操作，在服务测试前开启窗口，返回窗口 ID，之后按窗口和真实 queryId 读取节点记录。窗口默认 120 秒，显式时长最多 600 秒，同时最多四个，终态回执最多 4096 个片段。超限、过期或关联缺失必须令完整性检查失败，禁止返回伪零。

共享队列在首次创建时生成稳定令牌，节点窗口按物理对象去重，两侧端点分别登记。片段的逻辑关联和唯一物理对象数单独输出。窗口关闭或过期删除观测引用，生产清理继续按所有权执行。

例如，空闲基线为零驱动、零队列和零工厂，运行中五驱动四队列证明真实分配。取消后，所有关联片段预留必须为零，所有对象关闭，pending future 已完成或取消。最终还必须有每个已注销片段的零值回执，query 级零只作交叉核对。

交换池剩余与算子空闲字节在隔离环境与空闲基线比较，存在其他查询干扰时该次全池比较标为无效。源和 sink map、全局 reservation 队列长度、调度队列、注销日志及解释条目只辅助定位。待完成数必须按 future 的 isDone 核对，禁止把已取消但仍在队列的元素算作活动等待。

例如，空闲时交换池剩余 64 MiB、算子块剩余 128 MiB，运行时分别降为 60 MiB 与 120 MiB。取消结束应当恢复两个空闲值，同时全部片段账户为零且无注销失败。缺任一独立证据时，验收不能报告资源归零通过。

接口只为单节点、单次验收提供生命周期及内存读取，C 继续负责运行指标协议、CPU 与吞吐采样和跨节点合并。B 脚本可以汇集本地回执作断言，禁止将其称为 C 已实现。

### 隔离服务与确定性输入

候选与对照分别部署一个 ConfigNode 和两个 DataNode，目录、端口和数据均隔离。候选开启对应扫描功能，对照最后一步必须明确 DOP 为一。运行前验证真实注册节点数，运行后核对实际驱动、唯一物理 ID 和加载 JAR。

每次服务验收启动前必须保存六节点配置文件原字节、权限、SHA、开关值和启动参数。只修改隔离验收目录的配置，保留独立回滚副本。成功、查询失败、启动失败和取消都必须进入清理，服务停止后恢复配置并逐文件核对原值，任何恢复失败单独报告。

例如，时间分区与有序扫描开关的初值均为 false，用例开启为 true 后必须恢复 false。对照 DOP 和候选 DOP 各自恢复进入值。恢复后的文件 SHA 必须等于运行前快照，运行时开关以该次加载记录核对，禁止只读文件推断已加载值。

固定输入覆盖多设备多分区、单设备、单分区、空输入、null、时间边界、时间过滤、设备 limit、全局 limit 与 offset、有序重复键、过滤 diff 退回及倾斜分区。32 桶查询级兼容用例也在此阶段执行，B4 通道测试单独保存。

32 桶用例必须由验收入口直接绑定一个生产纯 sink 片段，并接收原分析得到的类型和输入扫描计划，修改仅限独立验收形态，保持生产资格守卫。先证明一个 sink、32 个真实 channel、一个源记账键与预期路由，再跑相同拓扑的 A 基线和 B 候选，并以 DOP 为一和确定性预期检查结果。

如果普通 SQL 规划器无法产生 32 桶纯 sink，runner 必须使用现有计划构建入口在隔离用例中组装该真实片段，禁止拿两个桶的 SQL 结果替代。验收工具只服务测试，入口和计划 SHA 必须冻结，片段执行继续使用生产 factory、exchange、MemoryPool 和 DataNode。可实施性由 B0 冻结该形态确认，B6 完成查询终态与完整结果检查。小型输入验证结构与结果，资源进展另使用足以触发背压的输入。

B0 必须确认该入口能构建、序列化和绑定实际节点，保存源纯 sink 的完整对象身份清单与计划 SHA。B6 还必须收集所有桶结果到最终查询结果，保存每桶预期与完整多重集，空桶必须正常结束。这个输入拓扑的基线对照也由同一 helper 构建，DOP 为一只控制扫描执行，不能把 32 个逻辑桶改为一个。

## 断言的反向核查

B 必须对核心断言做独立故障副本验证，避免测试只确认实现自己的输出。故障副本仅位于隔离目录，生产工作区和有效冻结依赖保持原样。反向验证成功指的是目标断言确实失败。

覆盖故障复制一个分区，有序故障改用 Collect，资源故障漏登记一条队列，清理故障跳过首个驱动关闭。另用隔离副本破坏基线额度，验证非法单块异常与释放断言。资源计数副本还必须在生效额度正确时被对象数与 nominalShareBytes 断言拒绝，清理副本必须被片段账户及注销回执拒绝。五类核心故障分别保存证据，轮询两条轨迹变异附在同一合同核查中。例如，漏登记后独立对象清单包含八项而冻结计数只有七项，计数断言必须拒绝该结果。

退出条件：五类故障各命中预期断言，原始实现对应测试通过，运行来源证明执行了指定副本。例如，故障副本的类 SHA 与实际加载类 SHA 必须一致，禁止把工作区通过结果当作副本验证。
