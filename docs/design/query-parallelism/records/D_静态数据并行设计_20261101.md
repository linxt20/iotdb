# D 静态数据并行设计

目的：规定表模型查询执行前的扫描并行度、工作划分、计划身份和验收方法。

摘要：相同设备数量可能对应不同扫描成本，静态计划需要稳定分配工作。D 从配置及存储元数据生成不可变计划，再通过公共构建器创建流水线。计划身份进入 C 的片段运行快照。资源准入在算子构造后执行。

结论：D 覆盖设备、时间分区和已证明自然顺序的扫描。纯规划器提供唯一并行度选择，运行中的驱动保持原归属。原因分类遵守批准的显式映射。生产身份与各项验收状态统一由 [A–D 完整核查](A-D_完整实现补全核查_20261102.md) 维护。

## 未决问题

- 性能倍率采用 3.33 倍还是 2.95 倍，等 sxing 决定。
- hash join 是否进入生产规划路径，等 sxing 决定。
- CPN 是否进入论文正文，等 sxing 决定。

## 扫描分配背景

一个扫描可以拆给多条驱动，但每行仍须恰好读取一次。分配结果需要可重放，才能区分算法变化与运行环境变化。完成要求同时检查工作覆盖、业务结果和真实执行身份。

例如，十二个设备分给四条扫描驱动时，设备集合的并集仍须为十二，交集必须为空。根合并驱动负责汇合结果，其自身不重复拥有这些设备。

D 的调整发生在执行资源构造前。执行中迁移、历史反馈发布与动态阈值由 E 的独立方案处理。

数据来源：工程为 sc01 `/root/iotdb`，分支为 `feat/next-p0`。固定基线为 `8d5d9c6a2c838e42f21be9ebd3278151fb75c520`。工作区源码由 A–D 核查的最终 manifest 绑定。

## 输入与时序

输入来自配置上界、设备集合、时间分区、已有成本和顺序证明。属性守卫先判断拆分安全性，纯规划器再给出计划，公共构建器随后创建算子及流水线。完整树建成后冻结资源，最后执行一次内存准入。

全局 limit、offset、共享溢写源和缺少顺序证明等限制继续使用既有安全判断。安全回退返回包含实际工作的串行计划。没有管理扫描的交换根片段保留拓扑身份，扫描并行度为零。

例如，扫描控制值为一时，扫描身份仍列出全部设备工作。根片段没有扫描时，工作列表为空，其交换边仍须保存。

数据来源：配置上界统一名为 `inputDop`，由 `LocalExecutionPlanContext.getDegreeOfParallelism()` 读取。本地入口为 `LocalExecutionPlanner.plan()`。扫描生成器为 `DataNodeTableOperatorGenerator`。计划计算与执行构造分别为 `ScanParallelPlanner` 和 `LocalScanPipelineBuilder`。冻结为 `freezeResourceQuota()`，准入为私有 `checkMemory()`。

## 不可变计划与身份

计划保存模式、输入上界、目标、成本和退回原因。每个工作单元具有结构化源键，设备模式以设备组表示工作，时间分区模式组合设备组与分区组，有序模式保留单设备扫描及桶内合并。

源键包含查询、片段、计划节点、模式、分区和设备组。规范编码生成稳定源 ID，禁止从节点后缀推算身份。桶保存实际工作集合和累计成本，构建后关联实际流水线。

例如，两个扫描源各自有桶零时，它们的源键不同。片段组合身份必须区分两者，禁止后一个源覆盖前一个源。

数据来源：源身份为 `ScanParallelPlan.SourceKey`。工作与桶对象为 `WorkUnit` 和 `Bucket`。独立计划校验和由 `StaticParallelPlanChecksum` 按显式字段及 UTF-8 规范顺序生成。

## 并行度与稳定分配

目标并行度受配置上界和工作单元数共同限制。内存瞬时余量不参与这个公式。一个工作单元或配置为一时，生成串行计划。

例如，配置上界四而工作单元只有三个时，目标为三。相同配置及元数据必须产生相同目标。

数据来源：公式为 `targetParallelism = min(inputDop, workUnitCount)`。空输入使用串行空计划。基线估计器 `decideParallelScanPipelineNum` 只服务未接管路径，禁止覆盖已选目标。

有成本时，规划器按成本降序和稳定源身份排序，再把下一项放入累计成本最小的桶。平局按桶编号选择。成本缺失时采用确定性等量分配，并记录缺失原因。

例如，成本九、六、三、二分到两个桶，先放九和六，再把三放入第二桶。两个桶均为九后，把二放入编号较小的桶。重复输入必须得到相同映射。

负元数据、long 溢出与异常分别由既定校验及饱和计算处理。发生计划错误时，完整回退保证工作集合保留，禁止发布部分计划。

数据来源：计算与基础测试为 `ScanParallelPlanner` 和 `ScanParallelPlannerTest`。确定性与覆盖测试为 `StaticParallelPlanDeterminismTest` 和 `StaticParallelPlanAccountingTest`。原因同时保留 raw 与 canonical 两项。

## 退回原因

D 的原合同把正常资格退回与计划生成异常分开。原始原因必须保留，规范原因按固定类别映射。验收先核对规范类别，再核对原始值及实际计划。

下表定义规范类别的使用条件，读者可以据此核对每一份计划和运行响应。

| 规范类别 | 使用条件 | 原始原因 |
|---|---|---|
| `NONE` | 已选并行或正常串行 | `NONE` |
| `PARALLEL_SCAN_NOT_SELECTED` | 基线未选择并行 | 保留原值 |
| `ORDERING_NOT_PROVEN` | 自然顺序未证明 | 保留原值 |
| `EMPTY_INPUT` | 工作集合为空 | 保留原值 |
| `SPILLED_DEVICE_ENTRIES` | 设备集合溢写 | 保留原值 |
| `ESTIMATE_UNAVAILABLE` | 成本估计缺失 | 保留原值 |
| `INVALID_COST` | 负成本或溢出 | 保留原值 |
| `PLAN_ERROR` | 真实计划生成异常 | 保留原值 |
| `UNSUPPORTED_TIME_PARTITION_RANGE` | 时间范围无法精确表达 | 保留原值 |

四类正常资格限制使用未选择并行类别，保留各自的详细原始值。它们返回包含完整扫描工作的安全计划，禁止标成计划生成异常。

下表给出四类资格限制的明确映射，供生产入口与独立测试共同核对。

| 资格限制 | 原始原因 | 规范类别 |
|---|---|---|
| 配置并行度为一 | `DOP_NOT_GREATER_THAN_ONE` | `PARALLEL_SCAN_NOT_SELECTED` |
| 只有一个设备 | `SINGLE_DEVICE` | `PARALLEL_SCAN_NOT_SELECTED` |
| 全局 limit 或 offset | `GLOBAL_LIMIT_OR_OFFSET` | `PARALLEL_SCAN_NOT_SELECTED` |
| 禁止扫描拆分 | `PARALLEL_SCAN_NOT_ALLOWED` | `PARALLEL_SCAN_NOT_SELECTED` |

例如，输入上界为一、设备数为三十二时，计划保留三十二个设备，并使用一条扫描驱动。原始值说明配置上界，规范类别说明没有选择并行。该执行没有计划生成异常。

时间范围类别沿用 B1 的已批准含义。运行间隔、分区起点或相邻起点无法精确对应，或半开上界无法表达时，计划保留完整设备工作及用户条件。资格退回和原始原因的验证状态由 [D 原因分类核查](A-D_完整实现补全核查_20261102.md#d-退回原因分类) 维护。

数据来源：原 taxonomy 位于 sc01 `/root/property-d-artifacts/D-docs-before-review-20261101-r5/D_静态数据并行设计_20261101.md` 的 143 至 156 行。该原件 MD5 为 `edcbd1da5beef69cdc676af6d218109e`，与第五轮审查的核对对象一致。审查报告为 `/root/w5-docs/D_静态数据并行文档审查第五轮_20261101.md`。四类详细原始值保留该 taxonomy 的非错误语义，源字段为 `rawSplitReason`。规范字段为 `canonicalFallbackReason`。时间范围责任见 [B 时间边界与克隆](B_静态数据并行统一实施记录_20261031.md#时间边界与克隆交付)。

## 三类生产扫描

设备路径按计划桶建立独立扫描。时间分区路径按设备组与分区组组合建立工作，后续写入时间分区上下文只传递已选结果。有序路径先证明自然顺序，再执行桶内合并与根合并。

例如，四条有序扫描各输出时间升序流时，根使用合并排序得到全部行升序。普通收集只保证汇合，无法证明整体顺序。

数据来源：`DataNodeTableOperatorGenerator` 的设备、时间分区和有序构造入口。自然顺序检查为 `isNaturallyMergeableDeviceScanOrder()`，公共资源构造为 `LocalScanPipelineBuilder`。

## 运行身份与指标复用

扫描计划、实际流水线和实际驱动数量分别记录。工作单元与桶按稳定源键组合，片段级桶列表再按组合顺序重新编号。该列表用于片段覆盖和展示，E 的逐驱动配对保存独立的源内编号。交换边使用实际片段、流水线、算子和源节点身份。串行源保留真实工作，无扫描根保留真实交换。

例如，四条扫描加一条根流水线时，扫描并行度为四，实际流水线数为五。两个量分别回答分配工作数和实际执行结构的问题。

生产端与接收端共用 C 的不可变快照适配器。驱动行数和块数来自根输出，算子明细保留实际类型化统计。墙钟缺失时保持明确原因，CPU 等无来源字段保留字段级不支持。

历史成本筛选器只提供只读纯函数帮助接口。D 生产规划使用静态元数据，E 新增独立历史存储和规划期读取。

数据来源：写入为 `FragmentInstanceContext` 与 `FragmentInstanceExecution.buildDriverSnapshots()`。适配与载体为 `RuntimeSnapshotAdapters` 和 `StaticParallelPlanIdentity`。视图与纯历史筛选为 `RuntimeSnapshotView` 和 `StaticCostCalibrator`。完整来源见 [C 字段来源](A-D_运行字段来源_20261102.json)。驱动按片段、流水线字符串、任务字符串的字典序排列。

## 校验与两侧比较

每份运行响应独立校验其内容。终态重复读取必须保持代次及校验和。计划校验和按本侧输入重算，候选和对照使用不同并行度时，身份可以不同。

例如，候选四条驱动各输出八行，对照一条输出三十二行，两侧业务覆盖均为三十二行。逐驱动条目分别验证，完整业务结果再跨侧比较。

禁止跨侧要求运行校验和、逐驱动计数或墙钟相等。两侧采样时间与执行结构不同。强制计数字段按本侧来源、非负性、身份及终态稳定性核对，有来源的墙钟按本侧范围核对。

数据来源：运行规范校验为 `RuntimeSnapshotChecksum.forFragment()`，其中包含采样时间。计划规范校验为 `StaticParallelPlanChecksum`。对应生产响应在 C 的统一适配器内自校验。

## 准入与退出

完整算子树只申请一次内存。普通准入失败按原查询错误合同结束，并清理本次资源。免检查与最高优先级零预留记录独立原因，禁止将其解释成容量测量。

例如，选定计划预留一百二十 MiB，结束时释放同一笔一百二十 MiB。禁止通过多候选成功预留试探可用并行度。

退出要求包括确定性、工作覆盖、三类扫描、真实身份、冻结统计、双节点和完整模块回归。双节点至少三轮，业务按完整多重集与规范 SHA 比较。有序查询还比较全部行序列。

任何一侧拒绝、缺失预期片段或回归未结束时，整体保持未完成。性能效果通过独立实验验收。

数据来源：[D 文件级规划](D_静态数据并行实现规划_20261101.md) 和 [A–D 最终核查](A-D_完整实现补全核查_20261102.md)。
