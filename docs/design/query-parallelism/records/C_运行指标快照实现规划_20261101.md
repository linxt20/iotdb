# C 运行指标快照实现规划

目的：固定 C 的生产文件、测试责任和退出证据，供实现与验收核查。

摘要：C 先固定统计来源，再建立不可变快照和冻结边界。协议、两个展示入口和逐来源抓取共用身份规则。无来源字段保留明确缺失原因。完整退出依赖真实 RPC 与全量回归。

结论：以下文件级处理已经进入源码，完整退出必须同时具备生产测试、真实 RPC 和全量回归。源码范围和执行结果由 [A–D 完整核查](A-D_完整实现补全核查_20261102.md) 统一维护。E 的普通查询历史发布按 E 的实施规划处理。

## C0 来源与执行身份

C0 保存实际源码、配置、执行入口和依赖身份。HEAD 之外的工作区内容必须进入源码清单。启动后还须记录类加载位置、进程命令和本地库身份。

例如，服务 JAR 与 Thrift JAR 来自不同构建时，预检必须失败。相同文件名不能证明相同执行版本。

数据来源：工程为 sc01 `/root/iotdb`，分支为 `feat/next-p0`。冻结输入、字段映射和执行证据统一由 [A–D 补全核查](A-D_完整实现补全核查_20261102.md) 索引。

## C1 值对象与派生

C1 用不可变副本保存查询、片段、驱动、算子和计划身份。校验和覆盖同一组规范字段。缺失资格分别保存在片段集合和字段映射中。

派生计数按稳定键求和，墙钟保留区间，零分母返回缺失。计划身份独立于采样校验和。驱动排序使用字符串字典序。

例如，同运行计数从二十到三十五时，行数增量为十五。完整计划身份、驱动集合和多计数字段的差分扩展由 E 实施，文件级要求见 E 规划。

数据来源：源码包为 `statistics/snapshot/`。构造和校验为 `RuntimeSnapshotBuilder` 与 `RuntimeSnapshotChecksum`。派生和差分为 `RuntimeSnapshotDerivation` 与 `RuntimeSnapshotDelta`。值对象和派生测试为 `RuntimeSnapshotValueTest` 与 `RuntimeSnapshotDerivationTest`。差分和计划身份测试为 `RuntimeSnapshotDeltaTest` 与 `RuntimeSnapshotPlanIdentityTest`。

## C2 生产冻结与故障清理

C2 在驱动侧维护纳秒墙钟，并从根输出边界读取行数与块数。片段终态在统计冻结之前调用幂等的驱动完成记录。成功响应显式设置成功状态。终态标志只由持有统计写锁的冻结路径设置，状态已完成的临时读取仍保持非终态。

冻结方法先读取末次时间，再读取首次时间，各捕获一次，并用捕获值计算墙钟。正式测试必须验证独立 getter 变化时仍得到同一组端点。缺失端点和时间逆序分别保留明确原因。

执行与初始化异常路径必须在发布失败前记录本次执行时间端点。测试必须让失败监听立即冻结统计，验证已开始的失败驱动保留首次、末次和正墙钟。finally、后续完成记录和关闭必须继续幂等。

终态异常必须释放统计锁并继续全部资源清理。统计读取禁止修改算子的兼容信息。规划引用在移交或失败清理后释放，避免终态上下文保留算子树。

例如，完成记录抛异常后，另一线程仍须取得统计锁。sink、驱动、交换内存及算子内存的释放断言仍须通过。

数据来源：驱动修改 `execution/driver/Driver.java`、`DataDriver.java` 与 `IDriver.java`。冻结修改 `execution/fragment/FragmentInstanceExecution.java` 与 `QueryStatistics.java`。时间捕获测试为 `FragmentDriverTimingSnapshotTest`。采集和生产测试为 `DriverMorselCompletionStatisticsTest` 与 `FragmentRuntimeSnapshotProductionTest`。故障和屏障测试为 `FragmentSnapshotFailureCleanupTest` 与 `RuntimeSnapshotStatisticsBarrierTest`，失败发布测试及精确运行证据由运行字段来源登记。

## C3 协议与展示

C3 通过结构化 Thrift 字段传输版本、代次、来源、驱动和计划身份。生产端与接收端共用适配规则。旧响应缺字段时保持缺失，实例不存在时返回 NOT_FOUND。

解释算子按实际交换上限分批输出，禁止把大型文本放进一个超限块。统计只构造一次，分批输出保留全部行序。单行自身超限时返回明确内存错误。

文本与 JSON 保留同一批驱动字段。有序合并根与扫描节点分别处理。兼容数值缺失、非法或溢出时，合并器保持缺失并继续清理。

例如，两个扫描的输出块数为四和六，合并结果为十。复制统计再合并后，类型化块数仍须为十。

数据来源：协议和 RPC 修改 `iotdb-protocol/thrift-datanode/src/main/thrift/datanode.thrift` 与 `DataNodeInternalRPCServiceImpl`。合并修改 `StatisticsMergeUtil` 与 `SpecifiedInfoMergerFactory`。两个统计 Drawer 共同接入展示。兼容与适配测试为 `RuntimeSnapshotTransportCompatibilityTest` 与 `RuntimeSnapshotAdaptersTest`。有序与分批测试为 `OrderedStatisticsMergeTest` 与 `ExplainAnalyzeOperatorTest`。两个 Drawer 的主回归单独核对。

## C4 逐来源抓取与对账

C4 为每个来源单独处理超时和失败，保留其余成功响应。终态专用入口在该来源的超时内等待冻结，实时入口保留单次读取。重复片段身份在提交任务前拒绝，禁止覆盖已有 Future。合并器检查预期、有意忽略、缺失和意外片段集合。端点和完整驱动归属进入有效性校验。

例如，预期三个片段而一个抓取失败时，必须保留两个成功片段，并标记缺失。恢复正确请求后，完整抓取重新取得三个片段。

数据来源：修改 `statistics/QueryStatisticsFetcher.java` 和快照包内的抓取、适配、合并类。生产调用点为 `ExplainAnalyzeOperator` 与 `CteMaterializer`。测试包括 `QueryStatisticsFetcherTerminalTest`、协议兼容和 `RuntimeSnapshotMergeAccountingTest`。

## C5 计划与指标复用

C5 从实际扫描构造路径读取计划身份。计划扫描并行度与驱动数量分别保存。没有扫描的根片段仍保存真实交换拓扑，扫描并行度为零。

全局调度器计数继续描述节点。逐驱动 CPU、输出字节和排队时间没有可靠来源时保持不支持。资源名义额度不能转换成实际预留或峰值。

例如，四条扫描流水线加一条合并流水线，扫描并行度为四，实际数量为五。E 必须读取这些现有字段，再决定自身需要新增的内容。

数据来源：计划写入修改 `LocalExecutionPlanContext` 与 `FragmentInstanceContext`。只读入口修改 `RuntimeSnapshotView`。字段责任见 [运行字段来源](A-D_运行字段来源_20261102.json)。覆盖和折叠测试为 `RuntimeSnapshotDriverCoverageTest` 与 `RuntimeSnapshotFoldIsolationTest`。实际构造由 `ScanSourceIdentityIntegrationTest` 验证。

## C6 真实验收与全量回归

C6 使用同一最终发行包启动候选与对照，每侧包含两个隔离 DataNode。设备、时间分区和有序查询分别执行三轮。业务结果与独立预期比较，有序查询额外比较完整行序列。

RPC 探针在有效查询句柄内验证完整、部分失败和恢复。每个场景重复读取两次，终态代次及校验和必须稳定。恢复指纠正不存在的实例请求，不承诺服务重启保留旧缓存。

例如，三个真实返回片段中的一个替换为不存在的实例时，必须得到一个真实错误和两个成功响应。恢复实例后，必须重新取得三个响应。

构建必须绑定本次依赖。英文、中文消息分别编译，并检查常量名及格式占位符一致。全量回归保留 ANSI、去色日志、Surefire XML、有效 POM 和 JVM 实际参数。

架构测试从实际 classpath 扫描全部生产包。测试类按测试产物识别，禁止改为名称匹配。资源不足时必须保留失败，禁止缩小规则或把未完成报告为通过。

数据来源：运行脚本、配置、完整结果和原始 Thrift 响应由 [C 实施记录](C_运行指标快照实施记录_20261101.md) 索引。执行前核对源码清单及两个发行 JAR 的 SHA。

## 退出核对

C0 至 C6 的退出要求保持全部有效。实现、单元断言、真实 RPC 和全量回归分别取证，任何缺项均保持未完成。

- 冻结、重复读取和异常清理必须通过生产入口测试。
- 协议兼容、缺失字段和完整身份必须通过正反测试。
- 派生、折叠隔离和展示必须使用独立预期。
- 真实双节点必须具备完整、部分失败和恢复回执。
- 完整模块必须结束，失败与错误均为零。
- 三端文档和字段来源必须完成哈希核对。

数据来源：设计语义见 [C 运行指标快照设计](C_运行指标快照设计_20261101.md)，退出证据见 [A–D 补全核查](A-D_完整实现补全核查_20261102.md)。
