## 三项阻塞处理

1. D0 清单按工作区实际 33 个改动路径补齐。主源码、测试文件和两个 snapshot 目录均逐项标记 `FREEZE_SHA`。D0 同时保存固定基线 SHA、工作区 SHA 或目录递归 manifest SHA。新增路径在固定基线记录 `ABSENT_AT_BASELINE`。
2. D5 将计划身份挂在 fragment 级 `FragmentRuntimeSnapshot`。`StaticParallelPlanIdentity` 保存 query、fragment、generation、planned DOP、actual pipeline、work unit、bucket、exchange edge、split reason 和 plan identity checksum。`FragmentInstanceContext` 写入，`RuntimeSnapshotBuilder.buildFragment()` 接收，`RuntimeSnapshotView` 从 `QueryRuntimeSnapshot.fragments` 读取。
3. checksum 口径拆为生产快照 checksum 和 plan identity checksum。生产 checksum 用于跨侧运行完整性比较。plan identity checksum 用于跨侧计划比较。Java `RuntimeSnapshotChecksum.forFragment()` 含采集时间，只用于单侧自校验，不参与 candidate/control 相等比较。

## 次要问题处理

4. 设计输出节补回 query、fragment、plan generation 和字段 validity 的身份绑定字段，并控制每句内部名数量。
5. D5 明确首版 operator 列表取空列表并记录 unsupported。四个无来源字段由 D5 适配器生成字段级理由。
6. 设计和规划判据 5 统一为按 driver 比较 rows、TsBlocks、generation、生产 checksum、plan identity checksum 和 validity，并统一 wall 支持状态对等规则。
7. 规划代码改动项改为单句条目。未决问题保持单句。
