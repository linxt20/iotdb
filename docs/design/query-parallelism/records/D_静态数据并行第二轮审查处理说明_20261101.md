# D 静态数据并行第二轮审查处理说明

## 对象

- 审查报告：`/root/w5-docs/D_静态数据并行文档审查第二轮_20261101.md`
- 修订设计：`/root/w5-docs/D_静态数据并行设计_20261101.md`
- 修订规划：`/root/w5-docs/D_静态数据并行实现规划_20261101.md`
- 上一版备份：`/root/property-d-artifacts/D-docs-before-review-20261101-r2/`

## 阻塞意见处理

1. 基线归属。设计拆分固定基线能力与未提交工作区能力。规划 D0 同时冻结两套身份，并明确 `ScanParallelPlan` 等对象当前不在固定基线。
2. 记录点归类。设计补充 SERIAL 行。1402 是 TIME_PARTITION，1462 是 DEVICE，1480 是 SERIAL，1510 和 1527 是 ORDERED。1480 的旧 reason 保留为 `PARALLEL_SCAN_NOT_SELECTED`。
3. DOP 公式。删除 memoryBudgetCap。公式统一为 `targetParallelism = min(inputDop, workUnitCount)`。内存字段不参与 planner 决策。`freezeResourceQuota()` 和 `checkMemory()` 只负责执行准入记录与检查。
4. 本地编排器。设计调用链与规划 D0、D2、D3 均加入 `LocalExecutionPlanner`。文档写明 `generateOperator()`、`freezeResourceQuota()`、`checkMemory()` 和 `setTimePartitions()` 的先后关系。
5. 分号规范。两份 canonical 文档已移除正文分号。正则命令中的字符也不再使用分号字符。

## 次要意见处理

6. 内部名密度。长字段清单移入表格或独立条目。正文只保留实现关系。
7. fallback 词表。设计改为三列表格，不再引用不存在的“下表”。
8. DOP 命名。两份文档统一使用 `inputDop`。规划保留工作区对象已有的该字段名。
9. 回退目标。负成本、溢出和校验失败统一退回完整 SERIAL 计划。
10. thrift 条件。D3 无条件修改 thrift 和生成代码。快照值对象、FragmentInstanceContext 与协议字段同步纳入接线，和 D6 RPC stub 判据一致。
11. 规划头部。头部结论只保留一段。调用链移到正文的“生产调用链和时序”章节。
12. 快照值对象。D0 和 D3、D5 明确列出 `QueryRuntimeSnapshot`、`FragmentRuntimeSnapshot`、`DriverRuntimeSnapshot`、`RuntimeSnapshotBuilder`、`RuntimeSnapshotMerger`、`RuntimeSnapshotValidity`。

## 复核结果

本地检查确认两份 canonical 文档均无分号字符。设计与规划都包含 `LocalExecutionPlanner`、SERIAL 记录点和 `inputDop`。规划包含全部六个快照值对象名。两份文档未运行生产代码和测试。

本轮没有修改 `/root/iotdb`，没有提交或推送。D 实现仍需在本轮文档审核通过后按 D0–D6 执行。
