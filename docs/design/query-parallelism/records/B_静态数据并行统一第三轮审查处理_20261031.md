摘要：第三轮指出轮询算例混合了树模型与表模型形态。本文将两种算例分开，并把额外额度明确作为测试注入。B0 退出条件、冻结调用重排、七对象反例和快照静止点也已具体化。本文只确认文档修订，运行通过情况由实施记录维护。

## 查询形态与测试背景

树模型与表模型使用不同的本地算子生成器，同一个算例必须对应真实可构造的计划。生产形态与人工注入的测试形态要分别保存。只在测试中出现的数值不能解释为生产行为。

例如，树模型轮询 sink 的最终额度为完整片段预算，表模型四扫描加明文 sink 的额度为该预算的五分之一。两者必须分别构造。

数据来源：[第三轮审查](B_静态数据并行统一文档第三轮审查_20261031.md)，MD5 为 `223d146a5e343707cb1356c09ade8823`，固定源码为 sc01 `/root/iotdb` 的 `feat/next-p0`，提交 `8d5d9c6a2c838e42f21be9ebd3278151fb75c520`。

## 轮询门限与反向测试

P1 表示关键行为与验证缺口，本轮 P1 采用两种生产形态加一个明确的人工注入测试处理。树模型四通道轮询 sink 的局部计数为一，表模型四条扫描加明文 sink 的局部计数为五。

例如，2 GiB 堆、32 查询线程的预算为 4,022,509 字节，树模型轮询门限为 3,016,881 字节，最终句柄额度为完整预算。表模型最终额度为 804,501 字节，并保持 PLAIN 策略。测试另手工注入 804,501 字节后，正确轮询门限仍须为 3,016,881 字节，错误重算副本必须被拒绝。

数据来源：[实施版设计](B_静态数据并行统一设计_20261031_实施版.md#多通道轮询门限)和[轮询门限与轨迹步骤](B_静态数据并行统一实现规划_20261031_实施版.md#轮询门限与轨迹)。

## 退出条件与执行顺序

四条 P2 属于退出条件和文字定位，实施版将其写成可执行要求。

- B0 必须完成 32 桶纯 sink 构建、序列化与节点绑定，保存计划 SHA 和对象清单。
- 反向计数使用七对象规范形态，故障登记数为六。
- 本地规划器的额度发布调用必须移到完整根内存估计之前，并断言顺序。
- query 汇总与片段和的比较只在无预留、释放和注销变动的静止点执行。

例如，六类定向测试通过而 32 桶计划尚未绑定时，B0 仍保持未完成。期间若账户有并发变动，一致性比较必须拒绝作为静止点证据。

数据来源：[B0 基线与身份](B_静态数据并行统一实现规划_20261031_实施版.md#b0-基线与执行身份)、[全局内存步骤](B_静态数据并行统一实现规划_20261031_实施版.md#全局算子内存与异常出口)和[片段读数与注销回执](B_静态数据并行统一实现规划_20261031_实施版.md#片段读数与注销回执)。
