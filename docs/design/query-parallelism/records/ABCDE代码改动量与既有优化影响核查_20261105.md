# ABCDE 代码改动量与既有优化影响核查

**目的**：回答并行改造的整体代码规模，以及它对既有谓词下推、计划优化、执行语义和性能路径的影响。

**摘要**：并行改造同时涉及规划、执行、交换、资源管理与统计，单看已跟踪文件的差异会漏掉新增组件。本文按明确基线统计手写源码，并沿优化后的扫描节点检查实际执行构造。新增专项比较功能组合下的扫描语义，并检查执行侧收到的过滤、分页和运行时过滤选项。功能兼容与性能开销分别判定。

**结论**：改造属于涉及多个查询子系统的扩展，生产 Java 相对 A 开始前基线净增约 1.38 万行。批准范围内的既有优化合同已具备源码核查与专项验证依据。性能路径存在新增元数据处理、计时和资源记账，功能验证通过只能说明执行合同成立，端到端性能影响仍需要独立对照实验。

## 核查背景

本轮核查关注优化结果是否经过并行拆分后仍到达实际扫描，以及新增处理是否增加原查询的执行成本。查询结果相同、原有优化保留和性能相同是三个不同判据。

例如，值谓词在优化器中正确下推，但子扫描丢失该条件，仍可能由上层过滤得到相同结果。此时结果正确，读取量却可能增大。因此本轮同时检查扫描条件与实际执行选项。

生产源码采用 2026-11-04 完整交付版本。本轮只扩展现有 JUnit 测试，未修改生产实现，也未 commit 或 push。

数据来源：sc01 仓库 `/root/iotdb`，分支 `feat/next-p0`，HEAD 为 `8d5d9c6a2c838e42f21be9ebd3278151fb75c520`。本轮原始统计、日志及回执位于 `/root/w5-docs-backups/optimization-impact-20261105-r1/`。

## 代码规模

相对 A 开始前基线，生产 Java 涉及 116 个文件，新增 14607 行、删除 822 行。测试代码量与生产代码量分别统计，新增组件也计入差异。

下表用于比较改动在生产、测试与协议等类别之间的分布，数字取本轮补测试前的冻结统计。

| 类别 | 文件数 | 新增行 | 删除行 |
| --- | ---: | ---: | ---: |
| 生产 Java | 116 | 14607 | 822 |
| 测试 | 87 | 17705 | 158 |
| 国际化 | 2 | 168 | 0 |
| Thrift 协议 | 1 | 108 | 0 |
| 其他文本 | 22 | 4049 | 264 |

“其他文本”包含文档、配置与研究辅助内容。新增行统计包含注释与许可证，表示文本差异量。生成代码、构建产物、证书和二进制 fixture 按独立类别保留，未计入手写源码规模。

相对 A 发布后的 HEAD，B 至 E 的生产 Java 涉及 101 个文件，新增 12922 行、删除 528 行。相对最初接手快照，整体生产 Java 涉及 126 个文件，新增 18774 行、删除 822 行。

这几个数字回答不同范围的问题。例如，只用 HEAD 的差异会漏掉已经进入 A 提交的实现。只用普通差异统计还会漏掉未跟踪的新源码。

数据来源：A 前基线为 `4b7f30fe56808eac3e2dfa25274d1afbd3f7c27e`，最初接手快照为 `5b32f717a59eb2299b8e498e0d76d2e3e43b428a`。逐文件新增、删除、分类与基线身份见本轮证据目录的 `change-size.json`。

## 影响范围

变化集中在分布式属性处理、本地扫描构造、交换资源、片段生命周期和运行统计。谓词下推、Limit/Offset 下推及其他逻辑优化规则目录相对两个对照基线均保持相同内容。

规则内容相同只证明优化规则继续存在。生产入口还需要保留原扫描的时间条件、值条件、列映射、扫描方向、分页与运行时过滤关联，并正确构造实际扫描参数。

有序扫描与无序扫描采用不同许可条件。无序扫描使用属性阶段的拆分资格，有序扫描使用完整自然顺序证明。全局 limit、offset 和设备溢写继续限制拆分。

数据来源：优化规则目录为查询引擎的 `plan/relational/planner/optimizations/` 与 `plan/optimization/`。高影响生产入口为 `DataNodeTableOperatorGenerator`、`TableDistributedPlanGenerator`、`LocalExecutionPlanner` 和交换、片段相关组件。

## 谓词下推与列裁剪

子扫描保留原值谓词，并将新时间范围与原时间谓词取交集。扫描选项构造继续把值谓词转换成存储过滤条件，实际读取列继续来自优化后的输出及列映射。

例如，原查询要求时间从三到十六，值大于零。时间分区子扫描可以进一步缩小时间范围，但其存储过滤必须仍拒绝负值、零值和空值，并接受正值。

新增执行测试直接读取实际扫描算子的选项并验证这些行为。设备、时间分区和有序模式分别覆盖动态开关关闭与开启。测试还检查传入存储扫描的传感器集合只包含所需字段。

计划专项另外比较九类 SQL 在四个功能开关全部十六种组合下的扫描合同，并分别覆盖属性规划关闭与开启。比较内容包括时间条件、值条件、输出列、类型、分页、扫描方向和 TopK 关联是否存在。

数据来源：新增正式方法位于 `DeviceTimePartitionMorselTest` 与 `PropertyDrivenDistributionTest`，原件与修改后的源码身份由本轮回执保存。

## 分页、排序与运行时过滤

全局分页的扫描继续使用安全串行路径，设备局部分页在设备归属不拆开的路径保留原参数。有序路径保留逐设备扫描及完整比较器的两层合并。

新增设备与有序执行测试检查实际扫描继续收到每设备七行限制与两行偏移。时间分区用例使用无分页输入，避免把跨分区的设备分页假设扩展到额外形态。原有 SQL 分页、排序与窗口测试同时纳入专项范围。

TopK 运行时过滤依靠生产者与扫描共享的过滤对象。新增测试在查询上下文登记一个对象，检查全部子扫描实际持有同一对象，防止克隆后的物理节点身份切断过滤关联。

例如，两个子扫描都保留同名过滤标记，但各自新建对象时，TopK 的阈值更新无法同时传播。同一对象身份断言可以识别这种连接丢失。

数据来源：已有测试包括 `LimitOffsetPushDownTest`、`SortTest`、`WindowFunctionOptimizationTest`、`TopKRuntimeFilterDistributedPlanTest` 和 `OrderedScanPipelineContractTest`，测试范围以实际全限定类名清单为准。

## 聚合、状态表达式与其他查询形态

专用分组哈希路径继续使用聚合准入和所有权检查。普通聚合、窗口、联合、公共表表达式（CTE）与连接保留各自的构建及安全处理，不能从扫描并行支持推断所有节点都允许任意拆分。

涉及 diff 的过滤继续采用既有安全路径。新增计划组合包含 diff 投影、聚合、分组聚合与有序窗口。已有扫描克隆测试还核查源字段、原查询条件和 TopK 标记的保留。

例如，diff 需要前后行关系。把表达式移入不同时间范围独立执行会改变边界，因此扫描范围拆分与表达式执行位置必须分别核对。

本轮专项包含已有静态、动态生产入口和单节点运行快照测试。真实文件读取与双节点结果继续引用其最终同版验收证据，新增算子构造测试的范围单独记录。

数据来源：[ABCDE 最终整体核查](ABCDE整体实现核查记录_20261104.md)及本轮 `selected-tests.txt`、`prior-optimizer-tests.json`。

## 性能影响

并行实现增加了可明确定位的工作，因此性能影响需要按查询类型测量。短查询、文件数量较多的区域，以及低选择率查询应当作为重点对照场景。

### 文件元数据处理

静态成本构造会读取区域文件列表，即使数据量并行度估算开关关闭也会执行。该估算开启时，并行度估算还会单独读取列表。源代码因此存在重复遍历和列表处理。

例如，一个区域有一万个文件，一个扫描源的两次列表读取会分别处理这些文件。文件大小对已关闭文件通常有缓存，对尚未关闭文件可能调用文件长度读取。额外遍历次数与真实存储访问次数分别计算。

这是可优化的确定额外工作。它是否造成端到端延迟退化，取决于文件数、缓存状态、扫描工作量和规划耗时占比。

### 驱动计时

驱动在每次执行切片结束时增加时间端点记录，其中包含同步与本机计时调用。动态开关关闭后，这部分用于 C 的统计记录仍保留。

例如，查询需要一千次驱动切片时，这项记录也执行约一千次。其占比需要同时读取切片数量与执行耗时，不能用查询条数估算。

### 构建与资源记账

资源身份登记、计划身份构造、整树内存估计和注销回执属于执行公共路径。资源观察窗口关闭时，观察事件采用空窗口快速返回，但公共资源管理本身继续存在。

例如，四条扫描流水线需要登记四个实际队列及其包装端点。并行度增加会同时增加构建与合并工作，最终收益取决于减少的扫描耗时能否覆盖新增成本。

### 动态反馈

E 开启后增加历史匹配、成本投影、终态载荷复制和有界历史写入。E 关闭的普通查询跳过新增终态反馈采集，已建立的 C 与 B 公共处理继续执行。

例如，大规模计划可能超过反馈保留预算。执行仍消费全部工作，但该样本不能用于后续成本调整。正确性和反馈可用性分别判定。

### 对照实验范围

性能对照应当分别比较接手快照、最终静态版本和开启反馈后的版本，并固定数据、查询、并行度与节点拓扑。谓词选择率、区域文件数、排序与分页形态需要分组记录。

例如，对同一条强选择性谓词查询，除了端到端耗时，还需要核对实际扫描行数、读取文件或块、流水线数和规划耗时。扫描量相同但规划耗时上升，说明需要继续分析新增规划成本。

本轮未新增端到端性能实验。3.33 倍和 2.95 倍的历史口径继续等待 sxing 决定，本报告不据功能结果选择其中一个数字。

数据来源：元数据入口为 `estimateDeviceCosts` 与 `estimatePipelineNumByDataSize`，计时入口为 `Driver.recordProcessTiming`，资源记录入口为公共登记表和内存注销回执。实际文件大小读取行为见 `TsFileResource.getTsFileSize`。

## 验证范围与执行记录

本轮采用同源 reactor 统一构建协议及上游模块，再执行选定的优化、规划与扫描专项。单模块编译要求已安装协议与源码一致，执行身份不一致时需要先修复依赖绑定。

新增测试共四个正式方法，其中参数化计划方法产生两个测试项。它们补充实际扫描参数与功能组合覆盖，仍受单元测试的输入及构造范围限制。

最终专项包含 71 个类、534 个唯一测试项，失败与错误均为零，跳过八项。结果由本轮 68 个未变化类、两个扩展类和配置隔离类的适用报告组成，逐类来源由最终回执保存。

八项跳过沿用既有范围，其中五项属于参数化方法的重复配置分支，另三项来自原有忽略项。新增五个测试项均通过。配置隔离检查同时验证新增参数化方法参与执行后的内部数量与全局配置恢复。

本轮只修改三个测试文件，包括两个扩展类和配置隔离类。生产源码与完整交付清单一致，原始失败日志、测试夹具原件与各次结果均保留。完整 DataNode 套件继续引用最终交付的验收，本轮范围为上述专项。

数据来源：本轮最终结果为 sc01 `/root/w5-docs-backups/optimization-impact-20261105-r1/final-verdict.json`。同版功能与机器验收的基础证据见 [ABCDE 整体实现核查记录](ABCDE整体实现核查记录_20261104.md)。
