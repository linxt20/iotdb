# ABCDE 整体实现核查记录

**目的**：记录五阶段最终实现的跨阶段接线、源码一致性与验收覆盖，供 sxing 核查总体设计的事实依据。

**摘要**：A 至 E 的阶段文档和验收记录分别绑定不同开发时间点，整体判断需要使用最终同版源码。本文重新核对工作区与冻结版本，检查关键生产调用顺序，并独立汇总原始测试 XML。本文还核对最终机器证据的范围与限制。面向读者的设计说明由配套总体设计单独提供。

**结论**：本轮核查未发现批准范围内新增的跨阶段接线缺陷或生产源码偏差，最终全量覆盖原合同及 E 专项。核查结论限定于已批准形态、最终测试范围和已执行机器场景。全 SQL 支持、性能倍率和混合版本升级分别按其独立边界处理。

## 核查背景

本轮核查确认五阶段是否在最终同一份实现中衔接，并确认已有证据是否覆盖该实现。核查通过需要同时满足源码匹配、生产入口连接、原始测试报告覆盖和机器证据范围明确。

本轮执行只读源码与证据核查，未重新运行构建、测试或服务，也未改动生产代码。最终源码与既有全量一致，未发现需要新增测试或重新运行全量的覆盖缺口。

例如，阶段专项通过只能说明其绑定版本和所选方法。只有最终全量实际包含这些方法，且被测代码与发行包一致，才能沿用到整体交付判断。

数据来源：仓库为 sc01 `/root/iotdb`，分支为 `feat/next-p0`，HEAD 为 `8d5d9c6a2c838e42f21be9ebd3278151fb75c520`。B 至 E 的实现仍包含工作区修改，最终实现身份采用源码清单。机器核查回执为 `/root/w5-docs-backups/abcde-final-20261104-r1/audit-final.json`。

属性提供者和强制器已经接入分布式输入合并入口。扫描资格继续由已证明的过滤与投影递归传播，有序扫描采用单独的完整顺序证明。通用属性强制与专用分组哈希路径各自保留职责。

核查还覆盖未知节点的保守收集、输出符号校验、全部输入保留，以及哈希描述子的两种序列化出口。最终测试包含属性提供者、强制器、决策、分组来源形态、所有权及单源分组规划。

## B、D、E 的构建与准入

静态与动态计划共用扫描构建器。生产顺序为准备历史、生成算子树、冻结扫描归属、登记根、冻结资源、整树内存估计、单次准入、定稿回执和最终流水线校验。

设备、时间分区和有序扫描均消费最终选定计划。时间分区的静态加权只在静态或保持静态分支生效，动态分组按桶内全部工作单元构造子扫描。有序入口按原证明顺序重排设备集合。

动态目标读取实际数据量估算后的输入上限。历史前次并行度取最近合格样本的真实桶数，可信准入拒绝优先。该链路由正式生产入口测试和实际文件估算场景共同覆盖。

例如，上下文为八、历史为四、实际输入上限为二时，最终目标为二。静态加权开关开启时，一桶 1024 个动态时间单元仍全部构造与执行。

数据来源：生产核查位置为 `LocalExecutionPlanner`、`DataNodeTableOperatorGenerator`、`LocalScanPipelineBuilder`、`ScanParallelPlanner`、`DynamicParallelPlanningService`、`DynamicCostHistoryStore` 与 `DynamicParallelScheduler`。最终正式测试包含 `DynamicParallelPlanningProductionTest` 的 26 项，以及静态确定性、工作归属和真实准入账户合同。

## 资源身份与失败清理

资源登记分别保存物理对象身份、包装端点与内存账户。冻结按真实对象计算诊断目标，并按兼容规则发布执行额度。父根接管和驱动接管分别移交清理责任。

规划失败保留全部已建工厂并清理未移交资源。准入拒绝先定稿回执，随后继续原失败清理。派发前取消建立取消记录，查询终止处理全部指定片段并清除共享映射。

无序收集使用就绪子流轮询，等待监听只执行唤醒。受检内存估计包含同时存活的子流保留量。统计或发布异常继续进入端点、驱动、文件和内存清理。

例如，同一队列的两个包装端点只对应一个物理额度身份，但两个端点均有终止责任。某个端点清理抛错时，系统继续处理其余资源。

数据来源：生产核查位置为 `LocalExecutionResourceRegistry`、`FragmentInstanceManager`、`TableReadyCollectOperator` 和 `CheckedTablePipelineMemoryEstimator`。最终 XML 包含 `LocalScanPipelineFailureIntegrationTest`、`PipelineDriverFactoryLifecycleTest`、`SharedQueueQuotaAtomicityTest`、`TableReadyCollectOperatorTest` 与 `CheckedTablePipelineMemoryEstimatorTest`。

## C 与 E 的统计及反馈

C 保留 IoTDB 原有计时、输出计数和统计传输入口。驱动输出读取根输出边界，墙钟来自本驱动端点。协议适配器核对查询归属、重复驱动、版本与校验和，缺失字段保留原因。

终态监听先幂等记录驱动统计，再冻结响应。普通查询动态采集单独隔离构造与复制异常。载荷在统计锁内复制，历史写入发生在解锁后、资源关闭前。上下文清理后，历史使用自己的副本。

规划准备固定可见历史集合，各源在实际输入形成后独立选择。多源归属保存为列表，片段展示桶编号与源内桶编号分别处理。第二版协议按明确版本分支校验，历史库与拒绝回执共同受容量约束。

例如，同一驱动同时拥有两个源的桶零时，两条配对都保存，驱动墙钟只保留一份，再按投影规则分配成本。后到的不完整样本也不能替换更早的合格前次宽度。

数据来源：生产核查位置为 `FragmentInstanceExecution`、`RuntimeSnapshotAdapters`、`RuntimeSnapshotChecksum`、`DynamicSnapshotAggregator`、`DynamicSnapshotHistoryStore` 和 `DynamicScanAssignmentRegistry`。最终测试覆盖终态故障、锁释放、协议兼容、覆盖投影、反馈预算、迟滞及准入优先级。

## 最终测试范围

本轮直接解析持久原始 XML，得到 840 个类、5327 个唯一测试，失败为零、错误为零、跳过 50 项，未发现重复测试身份。24 个订阅类由配置明确排除，排除与方法跳过分别记录。

原独立全量审计确认 69 项原合同和 249 项 E 专项均实际包含，并确认发行包内 4251 个服务类与被测 target 字节一致。中文专项为 12 类、92 项，沿用其同源码执行回执。

属性参数化测试的五项跳过来自重复参数分支的显式假设。这五个方法在另一参数分支实际执行，其中自行切换配置。其余跳过与明确排除名单按原 XML 保存。

例如，某方法先固定要求配置参数为 false，再在方法内部切换开关。该方法在 true 参数分支跳过属于测试的预定范围，报告仍如实保留跳过数量。

原完整套件收集器故障属于 `/proc` 观察竞态，最终结果依据同一次 Maven 调用的原始 XML、provider、类加载和内核退出记录恢复。核查采用最终恢复回执，并保留原失败记录。

数据来源：正式全量根为 `/root/rivermind-data/iotdb-e-acceptance-20261104-r4/full-r1/`。最终结果为 `full/verdict-recovered-r2.json`，独立审计为 `full-independent-audit-resumed-r2/independent-full-verdict.json`。本轮逐 XML SHA、跳过方法及排除名单集中保存在 `audit-final.json`。

## 机器验收范围

E 最终持久机器证据覆盖单、双 DataNode 的完整业务结果、四类动态动作、真实资源字段、准入拒绝和终态清理。实际文件估算场景同时比较三轮完整 24000 行结果。

边界场景包括时间加权两档的一桶 1024 子扫描和有序 16 设备。时间边界拓扑虽然有两个 DataNode，单 region 只有一个扫描节点，该场景按单扫描节点边界解释。普通双节点业务另有真实双扫描节点证据。

准入失败 SQL 用于验证拒绝及释放，业务成功由独立普通查询证明。免检查与最高优先级零预留两个例外单独验证。普通受管源的真实物理对象、记账键和名义份额均有正值。

例如，一份拒绝核查回执可以通过，但其业务成功标志仍为 false。整体退出由业务、资源和边界各自的完整证据共同判断。

数据来源：持久运行根为 `/root/rivermind-data/iotdb-e-acceptance-20261104-r4/runtime-r1/`。核查入口分别为 `business-envelope-audit/verdict.json`、`refusal-verifier/verdict.json`、`boundary-verifier-r3/verdict.json`、`estimation-native-audit/verdict.json`、`managed-resource-audit/verdict.json` 与 `loaded-runtime-identity-audit-r3/verdict.json`。
