# D 静态数据并行第三轮审查处理说明

## 对象

- 审查报告：`/root/w5-docs/D_静态数据并行文档审查第三轮_20261101.md`
- 修订设计：`/root/w5-docs/D_静态数据并行设计_20261101.md`
- 修订规划：`/root/w5-docs/D_静态数据并行实现规划_20261101.md`
- 上一版备份：`/root/property-d-artifacts/D-docs-before-review-20261101-r3/`

## 四项阻塞处理

1. C 快照值对象当前只有测试接线。规划 D5 现在明确写出 `RuntimeSnapshotView`、builder、merger 的现状，并把 `FragmentInstanceExecution.buildDriverSnapshots()` 到 Java 快照值对象的生产适配列为 D5 必做工作。D5 不再只增加 view 方法。
2. wall 字段改为可降级项。wall 有值时比较。wall 无值时记录 `UNSUPPORTED_FIELD:driverWallNanos`，降级比较 rows、TsBlocks、generation、checksum 和 validity。candidate 与 control 的 wall 支持状态必须一致。
3. TsBlocks 与 rows 同级。设计、规划和退出判据都把 `driverTsBlockCount` 列为第一层强制字段。
4. 准入结果进入 D6。每次记录 `ADMISSION_ACCEPTED` 或拒绝理由。candidate 与 control 至少重复三次。双方每次都通过 `checkMemory()` 且准入状态一致后才比较结果。单次波动不直接下结论，三次仍不一致则失败。

## 次要意见处理

5. D0 SHA 清单补齐固定基线和工作区目标。新增 `datanode.thrift`、两个 Drawer、`TableDistributedPlanGenerator`、`IoTDBConfig`、`LocalExecutionPlanner`、六个快照值对象和 `RuntimeSnapshotView`。尚不存在的新增文件记录 `ABSENT_BEFORE_D`。
6. 两个不满足 3 乘 3 的小表已改为列表。输出字段和指标复用字段均不再使用两列表格。
7. 规划中的 D0、D3、D5 和数据来源长清单已拆为逐项条目。设计正文的高密度代码名句也已拆开。
8. D6 恢复完整 ANSI 去色命令：`sed 's/\x1b\[[0-9;]*m//g'`。字符类中的分号是 ANSI SGR 参数分隔符，属于命令字面量，不作为正文分号连接从句统计。

## 复核结果

两份 canonical 文档的正文分号为零。设计和规划都包含 D5 生产快照接线、wall 降级、TsBlocks 强制比较和三次准入验收。DOP 仍统一为 `min(inputDop, workUnitCount)`。本轮只改文档，没有修改 `/root/iotdb`，没有提交或推送。
