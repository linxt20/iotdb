# B 静态数据并行统一实现规划

目的：为实施者规定 B 的文件级修改、依赖顺序与测试退出条件，供 sxing 在实施前审核范围和工期。

摘要：B 需要把已有三条扫描构建路径的公共步骤集中到统一入口。资源治理还涉及本地队列、远端通道、完整内存估计和驱动创建失败后的清理。本文将工作分为冻结基线、纯拆分计算、公共构建、资源准入和真实执行验收。每一步都列出代码落点与可验证产物。

结论：B 按 B0 至 B6 顺序实施，每一步关闭退出条件后再进入下一步，预计单人五至八个工作日。首版沿用已有扫描资格、DOP 输入和静态分组配置，并补齐资源身份计数与异常释放。本文为待审规划，B 生产代码、单元测试和真实运行均尚未实施。

未决问题：性能倍数、生产哈希连接和 CPN 正文范围均等待 sxing 决定，B 按[设计范围](B_静态数据并行统一设计_20261028.md#术语与范围)实施。

## 查询拆分的实施背景

扫描分支增加后，系统必须继续读取同一批数据，并在需要时保持整体排序。实施者还必须证明资源不足或创建中断时，已经建立的执行对象都能释放。只移动代码或只比较最终行数，都不足以完成这项工作。

例如，三条分支中第二条创建失败时，第一条已经成功的驱动也必须关闭。若只关闭失败分支自身，查询虽报告失败，第一条驱动的队列仍可能保留内存。B 必须把这些责任写入同一构建流程并验证。

数据来源：代码基线为 sc01 `/root/iotdb` 的 `feat/next-p0`，提交 `8d5d9c6a2c838e42f21be9ebd3278151fb75c520`，行为约束由[B 统一设计](B_静态数据并行统一设计_20261028.md)定义。

## B0 基线与执行身份

B0 必须建立隔离的源码与运行身份记录，并保存后续比较使用的构造快照。实施者首先核对分支、提交、工作区差异、四个已有测试类和 A 的最终回归证据。保留存量未跟踪安全资源目录，禁止将其混入 B 改动。

执行前记录必须包含真实入口与 driver 的绝对路径及 SHA256、源码与 POM 哈希、测试清单、配置快照、JDK 与 Maven、classpath、实际 JAR 和本地库身份。启动后继续记录实际类来源与本地库路径。与 B 无关的权重项记录为不适用。

例如，同一个 Java 类在冻结发行包与工作区 target 中各有一份时，只有加载记录才能说明执行了哪一份。任何入口与清单不匹配都必须先修复绑定，再执行测试。

B0 的基线快照必须覆盖设备拆分、时间分区、字节加权、等数量对照、有序两层合并、过滤融合及各个退回条件。已有四类测试先单独运行，完整模块在 B6 验收。源码核查只能作为定位依据，运行证据单独保存。

退出条件：四类定向测试全部成功，形态与资源对象清单可重放，配置在每个测试退出时恢复。例如，开关初值全开与全关各执行一轮后，退出快照必须逐字段等于进入快照。

数据来源与修改位置：基线证据为 `/root/property-b-artifacts/B-docs-20261028-01/source-audit.json`，拟新建仓库工具目录 `research/query-intra-parallelism-e2e-acceptance/static-scan/`，入口拟为 `run-baseline.py` 与 `baseline-manifest.json`，已有测试为 `DeviceTableScanParallelPipelineTest`、`DeviceTimePartitionMorselTest`、`LocalExecutionPlannerOperatorsMemoryTest`、`DriverMorselCompletionStatisticsTest`。

## B1 纯拆分计算

B1 必须先完成不可变描述与独立计算测试，再连接真实算子。输入使用设备快照序号、有序分区列表、可选权重和配置快照。输出包含模式、实际组、输入与目标并行度、排序证明、过滤融合标记和原因。

### 新增描述与计算类

描述构造函数必须复制列表与映射，拒绝重复分区和非法组，禁止保存可变上下文。计算入口必须保留设备数大于一、无设备溢写、下推限制和规划器许可等原资格条件。串行退回必须在建立任何子上下文前决定。

例如，设备数为一、分区数为三、DOP 为四，输出仍为串行。设备数为六、分区数为三、DOP 为四，输出的分组按设计的时间优先公式产生三条工作单元，覆盖预期十八个组合。

字节元数据采集保留在生成器与 TsFileManager 一侧，纯计算只接收快照值。缺失数据改用等数量分组，完整权重按确定顺序分配。计数乘法、累加和向上取整必须按[配置与估计边界](B_静态数据并行统一设计_20261028.md#配置与估计边界)处理。

退出条件：纯测试覆盖空输入、单设备、DOP 为一、上限夹取、重复分区、稳定同值、无元数据、负大小、long 溢出、乘法溢出及描述不可变，所有断言均通过。

修改位置与测试：新增 `plan/planner/ScanParallelPlan.java` 和 `ScanParallelPlanner.java`，新增 `plan/planner/ScanParallelPlannerTest.java`，从 `DataNodeTableOperatorGenerator.java` 提取 `partitionIntoGroups` 与权重分配的纯部分，入口暂以适配器保留，避免一次切换三种构建。

### 时间范围与语义复制

时间范围必须按运行时真实分区间隔与时间精度计算，源查询条件始终保留。实现者必须核查全局时间工具与目标数据库分区配置的绑定，绑定无法证明时在建资源前退回原扫描。边界预期必须独立于被测助手计算。

例如，输入时间区间包含负一、零和分区边界，测试必须逐点比较是否落入相应子扫描。针对 long 最大值，测试必须证明可读数据域内没有遗漏，无法表示的半开范围走已定义的边界退回原因。

退出条件：范围测试覆盖负分区、时间别名、原条件相交、多分区逻辑或、极值和不支持的配置，克隆前后原节点字段逐项一致。例如，子扫描缩小为两台设备后，原扫描仍包含六台设备，TopK 关联 ID 保持原值。

修改位置与测试：`DataNodeTableOperatorGenerator.java` 的 `requireTimeColumnName`、`buildTimePartitionRangePredicate`、`cloneSubScanNode` 及参数构造入口，扩展 `plan/planner/DeviceTimePartitionMorselTest.java`，独立纯范围测试可以加入 `ScanParallelPlannerTest.java`。

## B2 设备与时间分区公共构建

B2 必须把两条无序路径接入公共构建器，保持父 Collect、参数构造和源登记语义。B2 同时建立资源登记表的规划清理部分，B4 再补齐额度冻结。生成器负责采集输入与构造具体算子，构建器负责接线与所有权。每创建一个资源立即登记，禁止先批量构建再补登记。

公共构建器接收不可变描述和构造回调，逐组生成子上下文、克隆扫描、参数、扫描算子及可选过滤根。随后建立 sink/source、内存估计、工厂和父 ExchangeOperator。物理 ID 使用源节点与组序号，整数流水线 ID 继续由上下文共享分配。

例如，六个工作单元必须对应六个不同工厂、六个队列和六个交换源。每个估计必须关联正确父节点，根工厂仍由本地规划器最后追加。两源同组序号的物理扫描 ID 必须保持不同。

规划登记表必须提供独立关闭根登记与父子挂接接口。父子挂接完成后，子树关闭责任转移到父根，独立关闭集合只保留父根。端点中止项保持独立且幂等。

例如，两个扫描挂入组内合并后，清理只调用合并根的递归关闭。测试应当记录各算子的关闭次数，禁止以所有算子都至少关闭一次代替恰当的所有权验证。

过滤融合继续调用原执行构造，单独保留直接子扫描、无 diff 等限制。普通投影仍使用既有访问入口。所有构建回调必须传递原克隆语义字段，禁止以手写最小构造替代完整 clone。

退出条件：已有设备与工作单元测试通过，新增构建断言覆盖工厂、sink/source、源登记、父估计、唯一 ID 和无原节点修改，注入队列创建失败后已建对象全部清理。

修改位置与测试：新增 `plan/planner/LocalScanPipelineBuilder.java` 与 `LocalScanPipelineBuilderTest.java`，建立 `LocalExecutionResourceRegistry.java` 的清理与子上下文共享接口，修改 `DataNodeTableOperatorGenerator.java` 的 `constructParallelDeviceScan`、`constructParallelDeviceTpMorselScan`、`visitFilter`，保留 `constructTransparentMorselFilter` 的执行表达式入口，扩展 `DeviceTableScanParallelPipelineTest.java` 与 `DeviceTimePartitionMorselTest.java`。

## B3 有序构建与属性交接

B3 必须在同一构建器中保留每设备扫描、组内合并与组间合并三层对象关系。共用的是流水线接线，单设备扫描和比较器继续由有序模式的回调构造。有序入口继续使用忽略无序许可位的共同基础资格，并额外证明完整自然顺序。

例如，四台设备被分为两组时，每组包含两台独立扫描，并通过组内合并输出有序流，根再合并两条流。相同时间戳按完整排序条件比较，null 顺序与升降序必须继承原排序定义。

许可位为假但排序证明成立的样例必须继续形成有序并行。相同许可位为假时，无序扫描和直接过滤融合必须使用原入口。两条断言共同检查资格适配，避免共用助手扩大或缩小已有能力。

退出条件：两层合并结构、完整输出序列、反向扫描、标签加时间、相同键与 null、字段排序退回、时间位于非末位退回、列映射缺失退回均有断言，A 的属性合同与快照回归通过。

修改位置与测试：`DataNodeTableOperatorGenerator.java` 的 `visitSort`、`visitStreamSort`、自然顺序守卫和有序构建方法接入 `LocalScanPipelineBuilder.java`，新增 `plan/planner/OrderedScanPipelineContractTest.java`，沿用 `DeviceTableScanParallelPipelineTest.java` 的已有有序样例，分布式属性组件保持 A 的合同。

## B4 真实资源计数与内存准入

B4 必须让最终额度来自真实预留对象，同时保持原父子流水线计数算法。上下文的根构造和 schema 构造都初始化资源登记表，子上下文共享同一对象。纯扫描路径与已有通用交换路径必须统一登记，避免遗漏远端输入和输出。

### 资源身份与额度冻结

登记表必须按本地队列、远端 SourceHandle、远端 SinkChannel 的对象身份去重。source 注册可由原交换登记入口统一触发，sink 注册必须覆盖 IdentitySink、ShuffleSink 和通用树模型入口。现有计数的 add、set 和局部保存恢复保留原用途。

例如，两个 ExchangeOperator 包装同一队列时，最终对象数为一。一个 ShuffleSinkHandle 包含两个不同远端 channel 时，最终对象数为二。测试必须同时覆盖这两种对象数量与包装数量不同的情况。

额度冻结只允许执行一次，冻结后继续登记必须明确失败。预算为非正值、对象类型未知或除法产生零额度时，规划必须在调度前失败。零对象使用显式空分支，避免除零。

退出条件：多个兄弟上下文共享登记身份，本地流水线、本地跨片段、远端输入、远端输出、多桶 sink 全部计入，最终计数与独立对象清单一致。例如，八个对象、64 MiB 预算的最终单对象上界为 8 MiB，所有实际对象均必须满足此上界。

修改位置与测试：完善 `plan/planner/LocalExecutionResourceRegistry.java` 并新增 `LocalExecutionResourceRegistryTest.java`，修改 `LocalExecutionPlanContext.java` 的三个构造、`addExchangeOperator`、`setMaxBytesOneHandleCanReserve` 并增加 sink 登记入口，接入 `OperatorTreeGenerator.java` 与 `DataNodeTableOperatorGenerator.java` 的交换和 sink 访问方法。

消息修改位置：中英文 `src/main/i18n/en/org/apache/iotdb/db/i18n/DataNodeQueryMessages.java` 与 `src/main/i18n/zh/org/apache/iotdb/db/i18n/DataNodeQueryMessages.java` 同步增加预算非法、零额度、冻结后登记和不支持资源类型的错误模板，常量名与占位符必须一致。

### 本地队列的并发收紧

队列限额 setter 必须保证原子的最小值更新，并让读线程看到更新。登记表对普通本地 SourceHandle 必须取得共享队列，流水线和普通本地句柄均归一到该队列。输出展开使用既有 sink 接口逐 channel 处理。

例如，两个片段分别把同一队列收紧到 8 MiB 和 4 MiB，无论交错次序如何，最终限额必须为 4 MiB。双线程测试必须用可控制的屏障安排交错，禁止以偶然运行次数代替正确性断言。

退出条件：队列限额单调收紧，本地 source 的空 setter 已被显式适配，跨片段与流水线真实队列均达到上界，相关交换测试通过。测试必须检查最终数值和阻塞后恢复的进展。

修改位置与测试：`execution/exchange/SharedTsBlockQueue.java` 的 `setMaxBytesCanReserve` 与读可见性，`source/LocalSourceHandle.java` 的已有 `getSharedTsBlockQueue`，`sink/ISinkHandle.java` 的已有 `getChannel` 和 `IChannelRoutingSinkHandle.java` 的已有 `getChannelCount`，扩展 `execution/exchange/SharedTsBlockQueueTest.java`，在新登记表测试中使用真实本地句柄。

### 全局算子内存申请

本地规划器必须在算子树完整后冻结交换额度，再建立完整估计并进行单次全局申请。申请失败中止全部未移交资源，申请成功沿用片段终态释放监听。查询估计关闭且 quota 关闭时，继续使用原零预留语义。

例如，估计 96 MiB、剩余 64 MiB 的普通查询必须失败并清理。最高优先级路径按既有豁免返回值验证。内存估计和实际预留分别记录，禁止把估计数字写成实际已预留数字。

退出条件：申请调用次数为一、正常终态释放一次、失败与取消后资源恢复、估计关闭和最高优先级路径均符合原语义。例如，同一片段收到两次取消后，全局空闲字节仍等于进入值，禁止超额释放。

修改位置与测试：`plan/planner/LocalExecutionPlanner.java` 的数据与 schema 两个 `plan`、`checkMemory`，扩展 `LocalExecutionPlannerOperatorsMemoryTest.java`，若统一资源登记影响 schema 或树模型，同一测试阶段必须包含对应无扫描回归。

## B5 所有权移交与监控信息

B5 必须覆盖从建计划到提交调度器的全部失败位置，并复用既有统计记录通道。清理资源与限额资源分别登记。所有权从规划阶段移交到成功创建的驱动，失败工厂自身关闭与外层清理必须通过幂等状态避免重复通知。

### 驱动与工厂的释放责任

工厂必须提供生产可用的未消费资源关闭入口，成功创建驱动后把责任移交给驱动。片段管理器必须使用显式创建循环，保留已建驱动列表，并在任意失败时逐个关闭。最后一个根工厂的顺序继续保留。

工厂必须区分未消费、创建中、已移交和已关闭四种状态，并保护创建与关闭的状态转换。创建循环必须在移交前检查片段终态，取消发生在构造返回之后时，创建循环负责关闭尚未移交的驱动。工厂状态、登记表与创建列表只能有一个有效关闭责任方。

例如，用屏障把第二个工厂暂停在驱动构造返回与移交之间，再发送取消。解除屏障后，第二个驱动必须关闭，第三个工厂必须保持未消费并释放资源，禁止继续提交调度。

例如，第二个工厂失败时，第一个驱动和第三个未消费工厂都必须释放。第一次关闭抛异常后，清理循环仍必须处理剩余对象，并保留原异常及 suppressed 异常。工厂和登记表只释放自己仍拥有的对象。

退出条件：生成根失败、建立 source 失败、内存准入失败、首个与中间工厂失败、创建时取消、提交调度器失败、运行中取消均可恢复进入时的预留值，且所有 futures 进入可结束状态。
