# C 运行指标快照设计

目的：规定查询运行统计的来源、冻结、传输和合并方式，为静态扫描计划与后续动态策略提供可核查数据。

摘要：IoTDB 已有算子计时、输出计数和片段统计 RPC。C 复用这些入口，增加结构化身份、采样代次、校验和及缺失原因。生产端与接收端共用适配规则。真实验收同时检查业务结果、片段完整性和异常后的清理。

结论：C 复用 IoTDB 的采集和 RPC 通道，新增不可变身份、代次与缺失原因。CPU、逐驱动排队时间及峰值没有可靠来源时保留不支持。最终源码的验收状态统一由 [A–D 完整核查](A-D_完整实现补全核查_20261102.md) 维护，普通查询独立历史由 E 实施。

## 统计来源

C 复用 IoTDB 原有采集通道，新增部分用于表达原统计无法表达的身份与一致性。算子输出行数和 TsBlock 数来自计时包装入口。驱动输出只读取根算子的输出边界，禁止把内部算子的计数相加或取最大值。

例如，扫描读取十行，过滤后根算子输出四行，驱动输出为四。扫描十行仍保存在扫描算子的统计中。两者用于不同问题，禁止合并成十四行。

驱动墙钟使用本机纳秒时间。它覆盖设备、时间分区和有序扫描。兼容展示用的毫秒字符串继续保留，但结构化墙钟直接读取驱动字段。

字段缺失必须带原因。全局调度器计数描述 DataNode，不能替代逐驱动的就绪或阻塞时间。B 的名义额度描述分配目标，不能当作实际预留或峰值。

数据来源：根输出读取 `Driver.getRuntimeOutputRows()` 与 `Driver.getRuntimeTsBlockCount()`。原有算子通道为 `QueryStatistics` 与 `OperatorContext`。节点调度来源为 `DriverScheduler`。完整字段对应关系见 [运行字段来源](A-D_运行字段来源_20261102.json)。

## 运行身份

每份响应记录查询、片段、来源节点和实际端点。驱动身份包含所属片段、流水线和任务。接收方必须核对完整查询归属，禁止只按片段后缀匹配。

例如，两个查询都存在片段三，后缀相同仍是两个运行。查询一的驱动进入查询二的响应时，该响应必须标记身份错误。

节点 ID 使用实际 DataNode ID。端点来自服务配置，并与抓取时连接的端点核对。旧响应没有版本时标记兼容读取资格，缺字段保持缺失。

数据来源：协议位于 `iotdb-protocol/thrift-datanode/src/main/thrift/datanode.thrift`。Java 接收入口为 `RuntimeSnapshotAdapters.fromResponse()`。值对象保存不可变副本。

## 计划身份与数量

扫描并行度、实际流水线数和实际驱动数分别记录。每个扫描源保存真实工作单元、扫描桶和交换边。多源身份按源键排序后组合，禁止后一个源覆盖前一个源。

例如，四条扫描流水线加一条根合并流水线，计划扫描并行度为四，实际流水线数为五。没有扫描任务的交换根片段使用零扫描并行度，工作单元和扫描桶为空，交换边仍须真实。

串行扫描也保存实际工作单元。交换身份使用片段、流水线、算子和源节点组成的真实身份，禁止生成占位边。

数据来源：计划记录为 `FragmentInstanceContext` 与 `LocalExecutionPlanContext`。不可变载体为 `StaticParallelPlanIdentity`。视图入口为 `RuntimeSnapshotView`。

## 冻结与清理

终态监听先让驱动幂等记录完成统计，再构造并发布终态响应，最后释放执行资源。终态代次与校验和在重复读取时保持不变。状态到达 FINISHED 仍可能早于缓存发布，只有终态冻结路径才设置终态标志。显式读取只复制统计，禁止改写算子的兼容信息。

驱动发生执行异常时，失败发布必须晚于本次执行片段的时间端点记录。终态冻结可能由失败通知立即触发，因此时间端点必须在通知前可读。正常执行的 finally 仍负责其余结束处理。

冻结读取先捕获末次时间，再捕获首次时间，每个端点只读一次。墙钟由这两个捕获值计算。端点缺失使用不支持原因，末次早于首次使用时钟无效原因。例如捕获首次为 100、末次为 150 纳秒，墙钟为 50 纳秒，三个字段必须来自同一组捕获值。

例如，同一终态先后抓取两次，两份响应的代次和校验和必须相同。运行中采样可以生成新代次，禁止覆盖已经发布的终态。

统计锁必须在异常路径释放。快照构造失败后，系统仍须关闭 sink 和驱动，释放交换内存及算子内存，并清除临时文件。测试必须从另一线程重新取得统计锁，证明锁已释放。

数据来源：`FragmentInstanceExecution` 的终态监听与统计锁，`QueryStatistics` 的一次性快照屏障。执行失败顺序涉及 `Driver` 与 `DataDriver`。捕获与故障测试为 `FragmentDriverTimingSnapshotTest` 和 `FragmentSnapshotFailureCleanupTest`，失败发布的正式测试由运行字段来源单独登记。

## 响应生命周期

C 的终态保存保留 EXPLAIN ANALYZE 门控。普通查询没有终态响应时返回明确的非成功状态。实例和缓存都不存在时，服务返回 NOT_FOUND。

片段上下文受 IoTDB 查询清理控制，五分钟信息保留时间只是上限。查询关闭可以提前删除上下文，禁止承诺关闭后仍可抓取。E 必须在清理前复制反馈到自己的有界历史存储。

真实 RPC 验收使用仍有效的查询句柄。完整场景抓取实际返回片段。部分场景把一个端点上的实例替换为不存在的实例。恢复场景还原正确请求，再抓取同一终态。

例如，预期三个片段，其中一个请求返回 NOT_FOUND，其余两个仍须保留。合并结果必须标记缺失。恢复正确实例后取得三个片段，不涉及服务重启后的缓存保留。

数据来源：`FragmentInstanceManager.getFragmentInstanceStatistics()` 和 `cancelTask()`。真实探针及原始 Thrift 响应位于 [C 实施记录](C_运行指标快照实施记录_20261101.md) 指定的证据目录。

## 抓取与合并

抓取器为各来源设置超时，并单独保存成功、失败和端点信息。解释输出使用终态专用入口，按同一超时等待冻结响应。普通实时抓取继续读取单个采样。重复片段身份在提交抓取前拒绝，禁止覆盖另一个端点的任务。一个来源失败不能中断其他来源。预期返回片段与有意忽略的解释片段分别登记。

例如，预期集合为片段二、三、四，实际只取得二和三时，四进入缺失集合。收到片段五时，五进入意外集合。禁止把实际返回集合反过来当作预期集合。

响应校验和包含驱动、算子、计划身份和有效性。生产端与接收端使用同一规范规则。不同运行的采样时刻不同，候选与对照分别自校验，禁止要求两侧运行校验和相同。

数据来源：`QueryStatisticsFetcher.fetchAllStatisticsBestEffort()` 保留实时读取。终态读取使用 `fetchAllTerminalStatisticsBestEffort()`。合并入口为 `RuntimeSnapshotFetchResult.merge()` 和 `RuntimeSnapshotMerger`。

## 派生规则与展示

可加计数按稳定对象键去重后求和。墙钟保留每驱动值，跨驱动展示最小值和最大值。不同节点的本地纳秒时钟禁止相减。

例如，四条驱动输出五十、七十五、六十和六十五行，总数为二百五十。驱动墙钟分别为十和二十毫秒时，展示区间为十至二十毫秒。禁止把它们相加成查询耗时。

比率使用总分子除以总分母。分母为零时返回缺失。估计内存、预留内存和观测峰值分别保存，禁止相加。

例如，就绪二百、阻塞五十时，阻塞比例为百分之二十。两个计数都为零时，该比例缺失。缺 CPU 来源时，墙钟不能替代 CPU。

有序合并根与扫描节点分别保留。并行子扫描只按真实源身份折叠。非法、缺失和溢出的兼容数值保持缺失。复制及合并必须保留类型化 TsBlock 计数。

文本与 JSON 使用同一字段语义。驱动按字符串键的字典序排序，例如流水线十排在二之前。内部指标树键不向用户展示。

数据来源：派生为 `RuntimeSnapshotDerivation`。合并为 `StatisticsMergeUtil` 与 `SpecifiedInfoMergerFactory`。两个统计 Drawer 读取相同字段。

## 说明结果的分批输出

说明结果按实际交换字节上限分批发送。文本行的内容和顺序保持不变，统计只构造一次。最后一批输出后，解释算子才能完成。

例如，说明结果有十万字节，单批上限为四千零九十六字节时，必须输出多批。每批按实际字节数核对，拼接后的全部行必须与原说明一致。

单行自身超过上限时，系统返回明确的内存错误。关闭解释算子时，待输出结果必须释放。即使子算子关闭失败，也必须清除待输出引用。

数据来源：`ExplainAnalyzeOperator.nextResultBlock()`。测试为 `ExplainAnalyzeOperatorTest`。

## 验收与边界

C 必须同时通过值对象、派生、生产快照、协议兼容、锁故障、折叠隔离、Drawer 和真实双节点测试。全量 DataNode 回归必须完成，并保存退出码及逐类报告。

CPU、逐驱动就绪与阻塞、输出字节和内存峰值在没有来源时保持不支持。后续引入 CPU 采样时，额外耗时必须同时满足切片墙钟百分之一及五十微秒上限。逐驱动调度计时若新增，事件开销必须低于事件处理墙钟的百分之五。

例如，十毫秒切片的采样增量为六十微秒时，虽然低于百分之一，仍超过绝对上限，必须关闭该采样。C 的不支持分支不宣称完成这种采样。

数据来源：文件级验证责任见 [C 实现规划](C_运行指标快照实现规划_20261101.md)。生产执行和最终退出证据见 [C 实施记录](C_运行指标快照实施记录_20261101.md)。
