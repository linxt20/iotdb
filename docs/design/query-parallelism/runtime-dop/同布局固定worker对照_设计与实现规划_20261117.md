# 同布局固定 worker 对照：设计与实现规划

**目的**：为固定 DOP 和控制器消融提供相同运行图上的可执行对照。

**摘要**：现有 runtime 开关会同时切换扫描执行图。新增固定 worker 配置复用 runtime 的 lane、交换、准入、驱动和清理路径，只冻结 worker 初值并关闭自动成员调整。默认值零沿用现有自适应行为。该扩展是实验控制能力，不构成更强联合调度方法。

**结论**：先证明布局不变、实际人数符合配置、默认行为及终态清理不回归，再测固定一、二、四、八人与自适应模式。原 v6 发行包和已取得样本保持独立身份。

## 问题与比较范围

第一轮整体配置比较中，短有序查询的候选、对照中位延迟分别为 73.830ms 和 31.711ms。同 SQL 的独立资源审计分别创建十九个和三个唯一 driver ID，均完成关闭。对象数量不等于活跃 worker 数，这组差异也不能单独解释耗时。

对照需要固定源扫描工作、lane 数、排序前沿、哈希桶、交换协议、数据和资源限制，只改变初始 worker 与自动控制。普通串行、原生上游及旧静态执行图仍作为另外的对照，不与此处的同图消融混用。

## 配置与语义

新增 `runtime_scan_parallelism_fixed_workers`，默认零，取值范围为零至 1024。零沿用自适应策略；正数使获准 runtime 扫描组固定采用 `min(配置值, 实际 lane 数)` 个 worker。实验必须记录实际人数，不能以请求值命名未达到宽度的测量点。

该参数在 fragment 的根执行上下文创建时捕获，子上下文共享同一快照。规划生成原 lane plan 后再应用 worker 限制，不重新分组、不改工作 ID、不放宽查询资格。SERIAL、窗口及原生专用路径保留既有判断。

固定模式不启动控制器，也不提供可调整的组样本；显式内部 resize 调用应被拒绝。正常结束、取消、超时、执行失败仍经过原生停止、驱动关闭、统计冻结和资源结算。初始 worker 仍走原有批量准入，不能省略 CPU 或内存检查。

## 单元与集成验证

单元测试在既有 JUnit 体系补齐：配置默认值及非法边界；DEVICE、TIME_PARTITION、ORDERED 布局在不同人数下保持同一 plan 和覆盖；工作不足时的实际宽度限制；根、子上下文配置隔离；原生规划入口确实应用固定人数；最终登记及工作分配重建不会丢失固定标记。既有生命周期、调度、资源预算与控制器测试验证默认模式。

服务验证使用独立的新发行包及新部署目录。两侧均启用 runtime 并保留同一逻辑 lane 上限。普通 SQL 核对源与 FI 唯一身份、固定人数的实际初始事件、无已应用增减事件、完整有类型结果与全部片段资源回收。固定模式另重放 LIMIT、取消、超时和执行异常。自适应模式仍需真实先升后降。

标准验证采用 runtime-dop README 的 Maven 命令，设置 `GITHUB_ACTIONS=true` 禁用本地测试缓存，并保留新 tmpdir、classpath、XML 和原始日志。编译与服务前记录修改树、JDK、依赖锁、入口和发行包；启动后核实际加载。新旧发行包不共用身份。

## 性能矩阵

第一组在相同八 lane 下比较固定一、二、四、八人与自适应模式，覆盖全扫描过滤、两类多源聚合和短有序查询。每个测量点预热五次、保留十五轮成对样本和独立完整真值。每个配置使用新部署目录，不修改已有验收配置或覆盖结果。

第二组固定一名 worker，改变合法 lane 粒度，区分布局成本与控制成本。是否达到请求 lane 数必须由实际计划及资源证据确定。原生基线、谓词下推、窗口、FILL、TopK 和监控开销矩阵仍独立推进。

完整相同拓扑比较需要忽略查询、FI、生成代号等运行身份，并检查实际设备、时间范围、工作分配、源到桶关系及算子形态。只比较数量或原始查询 ID 相关 checksum 不足以证明相同布局。

## 完成条件与限制

完成条件包括新增单元测试、默认模式回归、固定人数服务证明、负例清理、可追溯成对结果及稿件范围更新。初始最多 1024 不表示机器可以准入该宽度；实际支持仍受 lane、工作量、CPU、内存和原生配置限制。

Electricity 下载、真实数据主矩阵、跨物理机扩展和更强联合方法不因该开关完成而视为完成。当前约 80GB 可用空间不足以同时部署两套各 50GiB 数据，较大规模需另作资源安排。
