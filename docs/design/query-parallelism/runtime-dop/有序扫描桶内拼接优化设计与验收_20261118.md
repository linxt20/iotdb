# 有序扫描桶内拼接优化设计与验收

**目的**：减少合法有序扫描中的逐设备算子构造，同时保持顺序、工作归属、进度和资源合同。

**摘要**：完整 Electricity 实验显示短有序查询退化，普通计划保留相同时间谓词，执行构造使用逐设备扫描和两级归并。本方案在每个桶内独立复用已有严格拼接证明，通过者使用一个多设备扫描，其余形态保留逐设备归并。

**结论**：修改限定于局部扫描树。逻辑 lane、桶归属、根部归并、队列、预付预算和 worker 控制保持既有合同。收益必须由新发行包的独立实验确定，v4 不利结果继续保留。

## 问题与适用范围

有序查询需要得到完整正确的行序列。把已经按设备键排序的多个设备分到同一桶时，设备间严格有序且设备内按时间有序，可以逐设备扫描并直接拼接。若时间键优先，或者不同设备的常量排序键相等，则两个设备的时间范围可能交叠，需要归并。

v4 在每个桶内为每个设备建立一个扫描算子，再归并到 lane 输出。一个含 184 个设备、八条 lane 的来源因此建立 184 个扫描叶子。严格拼接成立时，可减少为八个桶扫描，设备与时间覆盖保持相同。该例说明构造数量，不预先量化时延收益。

数据来源：sc01 实验根 `/root/rivermind-data/iotdb-paper-experiments-20261117`。v4 的完整结果和原生耗时在 `electricity-experiments-v1/measurement-01/`，普通计划在 `electricity-experiments-v1/ordered-diagnosis-01/`。原 v4 发行包和活动部署保持冻结，禁止覆盖其 JAR 或数据目录。

## 顺序证明与边界

外层已有资格检查要求普通表扫描、内存设备列表、支持的 TAG 或 ATTRIBUTE 常量键、最后的时间键及一致扫描方向。全局 LIMIT、OFFSET 和溢出设备列表继续按原资格处理。

对于多设备桶，复制原扫描节点并绑定桶内设备列表。复用完整常量前缀的 SQL 比较器，核相邻设备键严格递增，包含 NULL 位置、升降序、多键和 binary 字符串顺序。每个设备内的时间方向由外层资格保证。若前一设备的前缀严格小于后一设备，前一设备的所有输出都应排在后一设备之前，因而拼接保持完整排序。

单设备桶直接使用一个扫描。它的常量前缀在桶内固定，时间方向由外层资格保证。空桶保留 EmptyDataOperator。时间单键、多设备相等前缀、逆序或缺失证明继续使用原逐设备归并。混合桶分别判定，禁止把一个桶的证明推广到整个来源。

例如按客户端、时间升序，桶内客户端 a、c 严格递增时，a 的晚时间仍排在 c 的早时间之前。按时间升序时，a 的晚时间可能大于 c 的早时间，所以多设备桶仍需归并。

## 文件与处理位置

在 `iotdb-core/datanode/src/main/java/org/apache/iotdb/db/queryengine/plan/planner/DataNodeTableOperatorGenerator.java` 的 `constructParallelOrderedDeviceTableScan` 中，在空桶处理后构造桶扫描副本。单设备或严格证明成立时，使用既有串行扫描构造函数创建实际多设备叶子，再按原来源身份执行紧凑输出包装，返回同一类 PipelineSpec。

桶扫描使用唯一的桶内物理扫描 ID，父级归属仍由原来源和桶确定。显式桶绑定先清除副本继承的协调端设备数据集引用，再设置实际设备列表，使扫描总数与列表一致。逐设备后备也从这个已分离的副本派生。原协调端节点和数据集引用保持不变。外层 LocalScanPipelineBuilder、预算登记、队列、根部比较器和资源注册保持原调用路径。原节点的输出映射、时间谓词、字段谓词、TTL、源列表和排序属性由 clone 保留，原节点禁止原地修改。

已有 `OrderedParallelScanEligibility.canUseSerialConcatenation` 作为多设备证明入口。`mapBucketDevices` 保持原设备列表次序，证明针对实际选择出的桶列表执行。原 `AbstractTableScanOperator` 在扫描参数的设备总数与实际列表一致时提供设备完成进度，多设备扫描仍按实际设备逐个结算，关闭提前退出禁止虚增完成量。

## 单元与反向验证

在既有 `OrderedScanPipelineContractTest` 中补完整有序输出、每 lane 单扫描、设备覆盖、唯一 ID、未修改原节点、内存归还与恰好一次关闭检查。正例包含严格排序、升降序组合、NULL 边界和单设备桶。反例包含时间优先、重复前缀和未排序桶。保留原比较器、交换、队列和根部归并执行，存储叶子仍使用既有测试替身。

新增正例先在未修改生产代码上运行，预期因多余扫描或多余归并构造失败。修复后运行整个类和相邻规划、运行组、进度及失败清理测试。原混合桶测试按具体输入的预期形态核各桶，不以生产证明函数生成测试期望。

## 发行与服务验收

使用独立源码快照运行标准全量 DataNode reactor、双语言编译和干净打包，比较测试 class 与打包 class。新发行包标为 v5，原 v4 服务和材料保留。若标准回归失败，保留原报告并按原因修复。

新服务使用隔离目录和端口。完整数据逐列回读后，执行首轮十一查询族、额外多设备跨月排序，以及固定一、固定八和自适应扫描审计。核真实两个源节点、完整结果、设备进度、叶子数、实际成员与资源终态。

性能比较保留所有查询。优先以同一 v5 服务切换可证明路径与旧构造进行机制对照，或使用独立 v4 与 v5 配对部署，并明确对应的配置与布局范围。禁止仅把旧采样中位数与新服务单次诊断相除作为加速结论。
