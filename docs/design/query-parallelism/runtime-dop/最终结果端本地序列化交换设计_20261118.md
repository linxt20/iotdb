# 最终结果端本地序列化交换设计

**目的**：为同 JVM 的 runtime 最终结果边移除网络往返，保留原生 INPUT 预算、OUTPUT frontier 和客户端序列化结果合同。

**摘要**：普通 FI 使用双预付 typed link。最终结果端需要输出 ByteBuffer，且当前 INPUT 使用原生账户，因此复用 SourceHandle/SinkChannel 的预留、分片、任务归属和关闭状态机，仅替换同 JVM 最终结果边的传输适配。跨节点保持现有 RPC。

**结论**：普通 FI 双预付类型化连接与最终结果本地序列化桥已接入。重入关闭修复后 341 项专项、中英文编译、8,094 项全量及 4,518 个发行 class 对应检查通过；限定双节点服务与三轮动态升退通过。相同数据的 600 次开关实验已取得，但开启阶段区间跨一、参照有漂移，未建立稳定时延收益。开关保持默认 false；可选传输模式尚缺旧 JMX 的实时暴露。

## 账户与所有权

生产者仍用原 OUTPUT frontier，保留紧凑副本、schema、retained/encoded 上界及 response pin。消费端仍按原生 SourceHandle 的 INPUT 限额和逻辑块大小请求池空间，不新增 RFR、另一套准入或另一份 FI 预算。

本地调用复用内部服务的取块逻辑。在 RpcResponseLeaseScope 中完成独立字节副本，scope 退出前原生产者 backing 始终有 pin。消费端只接收脱离生产者存储的字节数组，因此之后 ACK、生产者取消或关闭不会使其持有未保护的借用对象。分片的 offset、totalLength 和范围校验保持原算法。

原生 INPUT 在序列化结果被取出时归还其池额度；返回后的客户端响应继续遵守 IoTDB 原有合同。此次不重新定义整个客户端网络响应的内存预算。

## 传输与身份

增加 LocalResultExchange，绑定完整 producer FI、channel、consumer FI、consumer plan node。取块和控制事件逐项核对身份。绑定输出 bounds 后才能取块，所有本地结果调用使用同一配对对象。

增加 ExchangeClientLease 适配现有客户端借还：远程持有真实 RPC client，本地调用 LocalResultExchange。SourceHandle/SinkChannel 的已有构造重载继续有效；新重载显式接受本地传输对象。manager 仅对启动开关开启、同 JVM 且由协调者在调度前明确登记的最终结果边创建它。

实际 Thrift 入口仍记录远程 payload；本地入口调用相同取块实现但不记为网络传输，消费端也按实际 transport 记录。远端入口不能由请求字段切换成本地计数口径。已有 task 计时仍表示实际内部任务调用，不能据此推断网络 RPC 数。必要时复用既有 LOCAL 计时标签，不新增控制策略指标。

运行资源快照增加可选 transportMode 元数据，区分 LOCAL_TYPED、LOCAL_SERIALIZED_RESULT、REMOTE_RPC。任务数、关闭回执与缓存量复用现有 endpoint getter。它不是新的准入变量或控制器计数器。真实服务验收须结合模式、完整结果、跨节点正向 payload、同 JVM RPC 事件及实际加载版本。

## 协调者清理

QueryExecution.releaseResource 当前直接 close/abort 后注销结果 INPUT 账户。新本地路径会在受保护 scope 中执行结果副本，协调者必须等待其 SourceHandle 的协调关闭 future，确认取块、ACK、关闭任务及回调实际退出后再注销账户。

增加一个可独立测试的结果端关闭辅助入口：支持 RuntimeExchangeEndpoint 的端点先请求协调关闭，成功后执行清理回调；其他原生本地或内存结果端沿用同步关闭。失败 future 不触发注销，并保留错误。回执交给已有 ResourceAuditManager 跟踪，失败通过已有日志体系反馈。重复调用仍由现有 resultHandleCleanUp CAS 控制。

## 最终结果端首次专项记录（历史）

当前实现已通过 340 项专项与中英文编译，三类故障注入已捕获。INPUT 的物理额度在本地任务退出前保持，待分配请求则先取消，以免清理等待其 continuation 时形成循环。配对 tombstone 保留到双方账户实际退休；发布与关闭声明原子排序，回调在锁外执行。

后续仍需当前源码的全量回归、发行 class 对应、真实双节点完整结果和资源/错误终态，以及同布局开关对照计时。启动开关默认关闭，尚未发布新性能结论。

## 2026-11-18 当前验收补记

当前结论以本节与开头摘要为准；前面的 340 项及尚未运行陈述是阶段性历史记录。新重入用例实际反向复现 Source monitor 内调用生产者关闭的问题，修复将声明与回调整体移到既有锁外执行边界。修复后的源码重新完成 341 项专项和中英文编译。

全量 reactor 8,094 项，零失败、零错误、56 跳过；DataNode 6,932 项。跳过集合与 v3 相同，两条已知 compaction 后台断言继续保留。干净发行的 4,518 个生产 class 与测试字节一致，服务 JAR SHA256 为 54fb231d9aab32751d13c0c1b751d67d0a93a633baf9d9577207df7cad62ee15。

五类正常查询两侧十份完整类型结果与独立 oracle 一致，开启侧同 JVM RPC 载荷块为零、关闭侧为正，跨节点发送接收仍匹配。两侧定向取消及开启侧超时、执行异常通过真实终态和资源结算。原生一秒终止宽限允许 FI 在 KILL 后进入 FINISHED；验收驱动改用精确活动身份、真实 KILL 确认、715 及全部终态和结算，未改生产终止器。省略真实 KILL、伪造确认的反向用例仍被拒绝。

新本地路径三轮实际由一增至五并退员，对照保持一人，六份完整输出正确；原生输入行数的离线派生每次为 9,404,416。固定一人的关闭、开启、再关闭实验共 600 次完整结果与原生 FINISHED 查询 ID 匹配；文件身份不变，但两个开启阶段的区间都包含一，后次关闭参照有漂移。不宣称稳定加速或控制器收益。

可选 transportMode 属于进程内 V3 视图，旧 JMX 接口尚未暴露；本轮服务证据依赖真实本地连接登记、独立跨节点正向载荷、同 JVM RPC 载荷为零及实际类身份，不冒充实时模式接口验收。
