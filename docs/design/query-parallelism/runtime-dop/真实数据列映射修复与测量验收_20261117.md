# 真实数据列映射修复与测量验收

**目的**：补充冻结设计说明之后的实际验证结果，并记录未关闭的动作合同。

**摘要**：物理输出 schema 修复通过反向测试、53 类专项、独立全量回归及真实 SQL 比较。Beijing 四查询的 160 次预热与测量全部结果正确，但没有建立自适应加速。R1 退员轨迹两次未触发。

**结论**：输出列映射错误的修复已有组件与真实 SQL 证据，整套新增 v3 动作矩阵仍未全通过。不能以完整结果正确替代实际增员后退员的验证。

## 组件与发行

三项新增断言在原生产代码上全部失败：列重排、重复列与子集、嵌套 OutputNode。修复后专项共 832 项、零失败、零错误、跳过五项。英文和中文编译、干净打包通过。

独立完整 reactor 为 8,047 项、零失败、零错误、跳过 56 项；DataNode 为 6,885 项、跳过 53 项。4,505 个生产类逐字节匹配 v3 发行 JAR。两条后台 compaction 断言与干净上游相同，继续登记，不能称为日志零异常。

## 真实 SQL 与测量

两侧分别导入并逐列核全部 420,768 行。列重排及重复别名/子集另有四次完整比较。四类查询共四十次预热、一百二十次测量，全部完整有类型结果匹配官方原始 CSV 真值。测量前完整回归已结束。

过滤扫描配对倍率 1.024，百分之九十五 bootstrap 区间 [0.966,1.056]；两侧独立审计均为两个运行组，每组实际一人。按站分组、过滤后分组和有序 TopK 没有运行组，倍率分别 0.911、0.799、0.926。这些不利的原生路径差异不能解释为动态 worker 策略收益。时标仍为可追溯名义小时轴，不声明真实 UTC。

## 失败与范围

七组确定性完整结果均匹配真值，但 v3 R1 在初跑及 Maven 结束后的重放中，均未观察到增员之后的退员。两次失败及资源原件保留，不能归因为 Maven 争用，也不能用旧 v6/v2 的成功动作替代。

完整跨运行设备/时间/bucket 内容、强基线、更大真实输入、跨物理机和独立联合选择器仍待补。实验扩展没有 commit 或 push。
