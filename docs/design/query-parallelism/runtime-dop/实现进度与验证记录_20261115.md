## 已写入开发分支的组件

### 固定逻辑扫描流的执行权

`RuntimeScanGroup` 和 `RuntimeLaneLease` 管理就绪、独占、阻塞及自然完成状态。同一逻辑驱动同时只能被一个工作者领取，令牌携带组归属和代次，重复归还与过期通知不会改变新领取的责任。阻塞流先归还执行权，再等待其 future，其他就绪流可以继续前进。

依赖引用保留原 Exchange 消费者关闭事件，不用生产者 EOF 替代。组只传递依赖或阻塞错误，不直接关闭算子，也不替片段决定错误处理。等待使用组级任意就绪通知，观察者取消不影响共享 future。

### 实际执行工作者

`RuntimeScanWorker` 实现 `IDriver`，可以在有界量子内调用已领取的原逻辑驱动。工作者正常退休停止领取，在当前量子归还执行权后结算自己的增量资源回调，不关闭逻辑驱动、扫描游标或输出流，也不减少原固定驱动计数。

退休确认和原生调度映射移除使用不同 future。当前组件有后者的确认入口，但原生调度器尚未调用它；不能把该接口存在当成任务注销已经接通。

扫描抛异常时，组先停止新增领取，再归还出错流，防止同步唤醒的其他工作者重新进入它。晚到的阻塞错误由组保留，并通知仍存活的替代工作者；退休工作者从错误通知中解除强引用。

### 驱动协作静止

`IDriver` 新增显式能力声明与静止请求，未知实现默认拒绝。原生 `Driver` 阻止后续处理量子，在当前量子退出独占锁后完成确认，既不取消原始算子或内存 future，也不要求调用者在量子内部同步等待自己。

确认复用原锁路径的关闭补偿，清理失败通过异常 future 暴露，多个观察者共享一次结果且取消相互隔离。`isFinished()` 可以在请求时立即为真，因此终态清理必须等待静止 future。该 future 不能禁止确认之后新发起的 `close()`。第二批新增独立关闭确认，等到算子关闭、资源释放和驱动锁退出才完成；`DESTROYED` 状态本身先于这些写入，不能作为关闭完成证据。

### 纯控制策略

`RuntimeDopPolicy` 在同一次执行组的样本上生成保持、增长或收缩请求。输入区分固定逻辑流、当前工作者、实际执行权、就绪流和背压流；样本身份、时间有效性、进度重置、冷却、迟滞、临近完成及资源上限分别判定。

未知和未支持指标没有数值，不当作零。策略不把墙钟当成 CPU，不分配资源、不提交任务，也不宣称已完成调整。现有静态决策、历史反馈和同查询控制的耦合仍待生产接线与实验验证；“静态加动态”本身不作为论文创新结论。

## 前沿内存与队列

`RuntimeFrontierReservation` 向真实 MemoryPool 一次性预留每流前沿容量，组内按 lane 划分不可借用的单块额度。队列使用真实驻留大小检验块上限，消费与关闭只归还内部 credit，最后一个 credit 归还后才释放组级预留。lane 与物理队列永久绑定，避免同 lane 被不同队列或游离生产者重复占用。

`SharedTsBlockQueue`、`LocalSinkChannel` 和 `LocalSourceHandle` 提供显式前沿模式，原构造入口保留原逐块池账户路径。新模式使用锁外通知 outbox，直接执行器和重入回调均不得在队列、sink 或 source 监视器内调用外部通知。回调失败不跳过 credit 结算，队列首次终态与原因决定另一端后续关闭行为，迟到 EOF 不把 abort 改成正常完成。

队列身份与实际组级账户已经有独立读取接口，但原资源注册表和审计仍使用队列身份。生产激活前必须补齐双 key 及实际账户去重。同片段全部组和 OUTPUT 句柄还必须使用同一权威总上限；尝试前沿准入会开启共享预算，失败后不能在同一片段静默回退。真实两层 MergeSort 的 DOP=1 活性尚未验收。

## 配额与统一清理

`ThrottleQuotaLimit.AdmissionTicket` 提供同用户 CPU 与内存整批原子申请，待激活和存活资源共用账本。正限额允许相等，零或缺失限额表示无限制，非法与溢出申请不扣账。ticket 支持所有权拆分和幂等释放，使工作者 CPU 与片段基础内存可以在各自生命周期结算。旧 check 方法保持原比较语义；只有默认原生任务和新增运行任务都接入这个账本后，才能宣称节点用户额度已统一保证。

`RuntimeCleanupCoordinator` 通过构建封闭屏障等待取消后的迟到所有者，随后依次执行停止、实际关闭、统计冻结、端点关闭、前沿释放、基础资源释放和账户注销。失败输出在驱动关闭前中止。停止或关闭确认的获取过程同步抛错时，仍尝试其他独立所有者，但保留依赖资源并返回错误，避免把未知执行状态当作安全退出。

该组件尚无生产构造调用。原有提前释放基础内存、清理查询上下文、异常兜底和调度器强制注销路径必须整体改绑，不能与新协调器并存。原生映射移除确认还必须放在关闭和冻结之前，排除迟到 blocked-to-ready 通知继续增加片段队列时间的可能。

## 接下来必须关闭的接线项

1. 静态布局与初始工作者数分离，保留原谓词、时间条件、投影、排序与源身份；在任何任务运行前捕获消费者关闭依赖。
2. 首批及增量任务提交，共享原 deadline、用户整批额度和计费上下文；正常退休走完成路径，禁止用 abort 代替降宽。
3. 统一异步终态，覆盖独立基础内存释放、查询上下文释放、固定 latch、调度器 abort 和交换账户注销等全部入口。
4. 队列使用真实前沿预留，验证 DOP=1 下满流、延迟较小首值、空流和两层排序合并均能前进；保持固定 Hash 桶与聚合状态归属。
5. 运行快照与控制器，区分逻辑流和工作者贡献，保留退休成员统计与缺失字段，记录请求、准入、实际执行和注销各自事件。
6. 真实 SQL 同查询升降宽、完整结果和顺序、异常资源回收、双 DataNode 候选与对照，以及性能对照实验。
