# 查询并行化与运行期 DOP 实现进度

**目的**：将源码接线、单元回归、实际 SQL 和性能证据按冻结版本分别登记。

**摘要**：最终 v6 已完成 51 类 808 项专项、DataNode 6875 项全量及中文编译；八组完整结果比较、19 个服务运行和 65 个 FI 资源回执均通过。本文保留 v3–v5 的诊断、失败及修订来源，当前验收只采用 v6 的实际发行与运行身份。

**结论**：最终 v6 的组件、完整回归、双语编译、双节点 SQL 和标准 CLI 验收均已完成。八组完整类型结果一致；扫描 worker 在同一 SQL 中实际形成 1→2→3→2→1。两条上游后台断言和测试缓存补跑按原件保留，不将有限验收外推为全部 SQL 或性能保证。

## 最终修订与验收结论

计划类型修订处理小整数常量折叠后的物理宽度差异：外部副本允许无损 INT32 到 INT64，并为全空列构造目标表示。后续 P1 核查发现，复制前的切块也必须按目标宽度计算；仅在 sink 做扩宽会使原生小宽度选出的整块超过已准入上界。v6 将目标模式贯穿估计、切块和独立复制，严格 codec 继续拒绝无关类型和缩窄。

超时修订将真实 QueryTimeout 原因传给同查询全部 FI/任务，不再替换成一般级联取消；过期 deadline anchor 不能停止替换后登记的任务。正常取消的原有原因仍按原合同保留。

| v6 门槛 | 实际结论 |
| --- | --- |
| 专项、clean package 与客户端 | PASS；808/0/0/5、51 类；94 个发行 JAR，CLI 仅使用该发行 classpath |
| 独立完整回归与中文编译 | PASS；8037/0/0/56，其中 DataNode 6875/0/0/53；中文编译退出 0 |
| 同包 R1/R2/R3/R7/raw | PASS；八组完整类型多重集，唯一键全序列与同时间组完整多重集分别检查 |
| 原生 LIMIT 提前结束 | PASS；两真实运行组，各初始 worker 一；扫描源输出 70000+90000=160000，完整返回 257 次 INT64 [1] |
| 定向取消 | PASS；真实 KILL QUERY、715 及三 FI CANCELLED，完整清理 |
| 原截止时间超时 | PASS；权威 JDBC vendor 720；每 FI 原 deadline 在采样到冻结间保持，状态 FAILED/FAILED/FINISHED |
| 原生 CAST 执行异常 | PASS；d063 尾窗实际执行后 vendor 701、两运行组、三 FI 终态和完整清理 |
| 元数据与 DIFF 标准 CLI | PASS；六次退出 0；SHOW 64/1 行，DIFF 64 行首值 NULL、其余 63 个 1.0 |
| 资源与发布材料 | PASS；19 个接受运行、65 个 FI，正向创建后全部责任结清，池恢复各自首 R1 纯净基线 |

最终正常结果分别为：R1 fullscan 4096 行、R2 两形态各 4096 行、R3 有序兼容和原生 early-stop 各 257 行、R7 两形态各 257 行、RAW 4750916 行。三方比较逐行保留重复次数，SHA 仅作补充。R1 一个组实际 1→2→3→2→1，另一组为 1→2→3；R7 两源位于两个 DataNode，两个 bucket owner FI 都在 DataNode1，不能误写桶跨节点。

完整回归首次 Maven 退出 0，但身份 guard 发现 pipe-api 两份 XML 恢复自 v4 缓存，因此原 runner_error 原封保留。关闭 Develocity 缓存后，七项测试真实重跑并替换汇总中的对应两份报告；最终 1147 份报告全部核对实际 tmpdir/classpath。DataNode 964 份报告从首次执行起均为真实 v6。上游原有两条后台断言在干净 master 精确复现，仍是本轮明确的测试限制。

实际服务仍有两次观察失败原件：小 LIMIT 对照首批 fetch 一次取完 257 行，服务已移除 query，故未捕获 roster；最终使用 fetchSize=1，在完整排空前捕获真实计划。立即 CAST 过快失败也未捕获 roster；最终用确定性 d063 最后分区尾窗自然触发同一 701，既不注入异常，也不修改生产行为。早失败不算通过。

最终验证后只修改八个可移植 SQL/JSON 配方文件，保持其入口与接受运行一致，另存旧除零 SQL。生产 Java、测试、配置、生成器、比较器和发行二进制未改；独立 CLI driver 仅去除类结束后的尾空行，重新编译的全部13个类与接受运行逐字节相同，见[格式等价回执](audit/final-cli-source-format-equivalence.json)；这部分 delta 由[独立清单](audit/post-validation-recipe-metadata-delta.json)登记，不回写旧冻结哈希。

数据来源：[SQL 独立审计](audit/sql-v6-independent-summary.json)、[八组完整比较](audit/v6-complete-result-comparisons.json)、[最终 CLI](audit/cli-v6-compatibility.json)、[统一验收摘要](audit/final-runtime-v6-validation.json)。

v4 的常量 LIMIT 曾因计划 INT64 与原生 INT32 不一致失败为 301；R5 曾取得 715 而非所需 720；旧 R6 除零表达式全量成功、结果为 NULL，不能证明异常。这些失败原件继续保存。R6 的新 701 不进入旧 raw0 消息兼容白名单。

## 性能与论文边界

本轮没有冻结的性能实验结论。正确性运行的单次耗时不用于更新 3.33 或 2.95 倍口径；两者的使用需由对应原始实验、环境和重复统计决定。

通用 hash join 是否进入生产规划、CPN 形式化是否进入论文正文，以及最终投稿拆分不由这份状态记录替用户决定。property enforcement 本身属于既有方法，论文需要解释 IoTDB 适配、执行机制和动静结合控制的独立技术价值。
