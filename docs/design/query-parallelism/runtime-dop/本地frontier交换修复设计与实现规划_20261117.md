# 本地 frontier 交换修复设计与实现规划

**目的**：恢复已启用 runtime frontier 时同一 DataNode 内的本地交换，减少已经观测到的回环 RPC。

**摘要**：620 个诊断查询的完整结果正确。逐查询、逐生产者、逐通道关联两侧载荷审计后，短有序查询在固定一人配置下有 96 个同 JVM 载荷块，关闭扩展时为零；两侧跨节点块均为 32。当前 frontier 分支明确绕过本地通道选择。修复需要保留双端预付、独立内存边界、序列、取消及结清合同。

**结论**：普通 FI 双预付类型化连接与最终结果本地序列化桥已接入。重入关闭修复后 341 项专项、中英文编译、8,094 项全量及 4,518 个发行 class 对应检查通过；限定双节点服务与三轮动态升退通过。相同数据的 600 次开关实验已取得，但开启阶段区间跨一、参照有漂移，未建立稳定时延收益。开关保持默认 false；可选传输模式尚缺旧 JMX 的实时暴露。

## 当前路径

启动开关关闭时，runtime 的 FI 边与最终结果边保留原 leased RPC。开关开启且两端同 JVM 时，普通 FI 使用 RuntimeLocalSinkChannel / RuntimeLocalSourceHandle，由 RuntimeLocalExchangeRegistry 配对；最终结果边使用 LocalResultExchange / ExchangeClientLease，在保留原生 INPUT 与预付 OUTPUT 的条件下进行本地序列化传输。跨 DataNode 继续使用 RPC。

QueryExecution 在 schedule 前显式登记最终结果消费者，manager 据此选择双方匹配的传输对象。manager 在构造时冻结开关，避免同 JVM 两端在不同时间选择不同模式。

旧 SharedTsBlockQueue 仍只承担扫描 lane 的单 OUTPUT 合同。普通跨 FI 双预付使用独立单槽 link；最终结果端复用原生 SourceHandle 的 INPUT，而不是冒用另一个 FI 的 frontier。

## 必须保持的合同

1. 普通 runtime FI 边的输入、输出仍分别预付。每侧 frontier 通过原 `bind` 校验 query、FI、pool、memory side 与 slot；不共享或冒用另一侧的身份。最终结果端目前使用原生 INPUT 账户，必须保留其预算和生命周期，不能声称它已有 INPUT frontier。
2. 同一物理队列只登记一次，生产者和消费者的关闭责任分别登记。队列、端点与名义/实际预留不能混成一个计数。
3. 只发布已独立拥有且满足 admitted schema、retained/decoded 边界的块。不得借本地优化移除边界检查，也不得把仍由扫描器复用的数组直接交给另一 FI。
4. 一个槽的块信用仍只占用一次。入队、交接、消费、取消之间有显式所有权转移，关闭与重复回调幂等。沿用现有消费者持有返回块时的原生内存估算合同，不制造未归属的保留区间。
5. FIFO、EOS、同键顺序及错误原因保持。消耗方提前结束会关闭生产责任；晚构造的对端不能复活已经取消的连接。
6. 不在 exchange manager 或队列 monitor 内执行可重入资源、完成或失败回调。构造失败不得以换传输方式再做一次准入来掩盖失败。
7. 跨 DataNode 继续使用现有受界 RPC。整个修复不改 hash 桶、source/work unit 归属或动态成员算法。

## 冻结传输选择

增加只在启动时读取的本地 frontier 开关，供同发行包的开启/关闭实验。它不支持热更新，避免同 JVM 两端在不同时间读取不同模式。每条边仍先遵守分布式计划已有的 runtime 协议标记，再在同 JVM 条件成立时选择受界本地桥接；跨节点不变。

本轮默认值保持关闭。限定正确性验收和开关实验不自动触发默认开启，特别是当前尚无稳定时延收益。实验显式绑定开关；不把可选路径完成报告为默认短查询性能问题已经解决。

## 结果端账户核查修正

QueryExecution.initResultHandle 经 createResultSourceHandle 登记最终结果边。消费端的 SourceHandle 没有 INPUT frontier，仍使用原生 INPUT 账户；生产者的 SinkChannel 持有 OUTPUT frontier。开关关闭或跨节点时走 leased RPC，同 JVM 且开关开启时走本地序列化适配。

本地取块在 RpcResponseLeaseScope 内生成独立字节副本，生产者的 response pin 保持到副本实际退出。取消先撤销尚待分配的请求，再等活动取块、分片和副本任务退出，之后归还已分配 INPUT。QueryExecution 等协调关闭成功后再注销捕获的实际 handle 的账户；错误回执保留。

普通 runtime INPUT 仍使用 typed receive。最终结果必须交给客户端独立 ByteBuffer，不把 typed 双预付端点当作原生结果消费者。客户端结果返回后的内存继续遵循原生合同，此次没有重定义整个客户端 RPC 响应预算。

消费端关闭与生产者发布在同一个元数据临界区排序，实际关闭回调在锁外执行；配对 tombstone 保留至两侧账户实际退休。详细合同和文件入口见同目录《最终结果端本地序列化交换设计_20261118.md》。

## 核心状态机与已执行验证

`RuntimeLocalExchangeLink` 当前只接受双端 RFR。边键由完整 producer FI、channel、consumer FI、consumer plan node 组成，跨 query 身份被拒绝。两端可任意顺序绑定，绑定未齐之前不能发送；边界必须与同一边已有的准入合同一致。

单槽按 COPYING → BUFFERED → CONSUMING → RETURNING 流转。发布前生成独立的受界副本。INPUT 信用在消费开始时取得，OUTPUT 信用贯穿副本生成和消费；两者结清完成后才重新开放槽位。消费者返回的 typed TsBlock 依照原有 ExchangeOperator 的 decoded-return 预算移交。关闭可立即封印连接，但活动复制或消费退出之前，关闭回执保持未完成。所有消费函数、future 通知和 RFR release 均在 link monitor 外执行。

## 最终结果端实现补记（2026-11-18）

最终结果端通过 LocalResultExchange / ExchangeClientLease 复用 SourceHandle、SinkChannel 的原生 INPUT、预付 OUTPUT、分片和任务状态机。取块在 RpcResponseLeaseScope 中生成独立字节副本，scope 实际退出后才归还生产者 pin。它仍需要序列化，不是零复制。

取消先撤销待分配的 INPUT 请求，再等取块与副本任务退出，最后实际归还已分配 INPUT。失败取块也在任务退出后归还额度。QueryExecution 通过协调关闭回执确认资源退出，再注销捕获的实际结果 handle 的账户；异步清理不读取重试后替换的 handle。失败回执保留，不触发强制注销来制造成功。

消费端关闭的 tombstone 保留至双方实际账户退休。生产者发布和关闭声明在同一元数据临界区排序，真实关闭回调在锁外执行，避免关闭事件先于发布而丢失。普通 FI 的独立双预付 link 保持原路径。

RuntimeResourceSnapshot 的 transportMode 是可选的传输来源元数据，区分 LOCAL_TYPED、LOCAL_SERIALIZED_RESULT 与 REMOTE_RPC。任务数、关闭回执和缓存量复用已有 getter。实际远程 Thrift 入口仍记录 payload，本地入口不冒充网络传输；真实服务的零回环判定仍需结合加载版本、来源模式和正向跨节点载荷，不能只看零计数。

详细文件与合同见同目录《最终结果端本地序列化交换设计_20261118.md》。启动开关关闭时仍保留 RPC；当前开关开启的两类本地传输均已完成专项验证。
