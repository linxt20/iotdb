## 1. 查询执行的背景

一条查询拆成多个执行分支后，结果仍必须满足分组和顺序要求。相同键需要在最终聚合前汇合，需要整体有序的父节点必须收到可证明有序的输入。扫描拆分还必须保持每行恰好读取一次。

例如，两个来源分别有键 a 的两行与三行，最终必须只输出该键的一个分组，计数为五。直接拼接两个局部计数会改变结果。因此，计划结构的正确性必须先于资源数量调整得到验证。

数据来源：代码范围见[整体设计](修改位置与整体设计_20261025.md)，属性语义和保留的专用路径见[框架设计](属性驱动并行判定框架设计_20261027.md)。

## 4. A 的实现依据

## 5. A 的验收方法

A 的验收同时要求组件断言、专用形状、同配置快照、完整模块测试和真实查询。命中某一源码位置只证明测试执行经过该位置，结果条件继续由对应断言验证。

完整模块测试必须核对 Java 声明中的实际类名，并逐类对应报告。架构检查遇到 OOM 必须报告断言失败，可用空间不足时必须终止该次运行。被终止的运行保留原始证据，完成状态维持待验收。

例如，一份清单包含三个可运行类时，必须找到这三个类各自的报告。某类缺失报告时，即使其余类均通过，该清单的覆盖仍未完成。配置隔离还必须保存进入值并在退出时恢复。

真实查询分别检查候选、关闭优化的对照和确定性预期。完整多重集、规范化 SHA、实际 DataNode 和片段所有权共同构成证据。空输入必须成功完成并返回预期空结果。

数据来源：功能与断言的对应关系集中见[测试核查](属性驱动并行判定框架测试核查_20261028.md)，原始退出、XML、实际类来源和查询结果分别保存在 A 的归档目录。

## 7. 工期与未决范围

A 的文件级规划以单人串行为依据，初始估计为九至十三个工作日。剩余工期由未关闭的验收项决定，完整模块回归失败会增加重跑时间，范围审核的等待时间单独记录。

## 8.1 A→E 大块任务路线

大块任务的依赖顺序为 A、B、C、D、E。本轮仅执行 A，以下各块描述后续范围。

### A 属性判定框架

A 统一属性计算、节点插入、退回原因和诊断，保留已经验证的专用执行形状。A 的全部验收通过后，实施者提交并推送一个完整提交。随后只编写 B 的设计与实现规划，B 的代码实施等待文档审核，C 至 E 保留为后续规划。

### B 静态数据并行统一

B 统一扫描工作单元、有序扫描和资源准入。它需要把计划资格与实际驱动构建条件连接起来，设计和实现均留待独立工作项。

### C 运行指标快照

C 核查并复用已有采集点，建立查询与片段级运行快照。现有统计入口提供核查基础，统一快照及其一致性规则由 C 单独设计。

### D 静态调度策略

D 规定可重现的资源分配策略，并通过统一测量协议比较结果和开销。已有 DOP 配置属于输入条件，策略的调度规则与效果由 D 的验收证明。

### E 动态并行控制

E 根据运行快照调整尚未启动的执行资源，并处理滞回、取消和资源释放。它依赖已经验证的计划结构、执行准入和统计快照，具体机制由 E 的独立方案规定。

数据来源：A 的详细依据为[框架设计](属性驱动并行判定框架设计_20261027.md)与[框架实现规划](属性驱动并行判定框架实现规划_20261027.md)，后续各块在完成自身设计前保持规划状态。
